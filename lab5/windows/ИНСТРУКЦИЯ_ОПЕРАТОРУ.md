# Инструкция оператору: съёмка кадров ЛР5 на Windows 11 ARM64

Документ для агента-оператора (человека или ИИ), который работает **на самой
Windows-машине**. Цель — собрать `Lab-05a/x/b/c.exe` и снять кадры харнессом
`lab5\windows\tools`. Всё, что ниже, проверено на macOS только в части, не
требующей Windows (см. `tools\README.md`, §10); шаги на Windows выполняются
впервые, поэтому после каждого шага есть критерий приёмки — не переходите
к следующему, пока он не выполнен.

## 0. Границы работы и стоп-условия

Можно: работать в консоли Windows, собирать exe, запускать `build.cmd`,
`run_lab.ps1`, `start_driver.ps1`, `capture_05*.ps1`, смотреть окна и кадры,
сохранять результаты в `lab5\windows\tools\shots`, `done`, `logs`.

Нельзя:

| Запрет | Почему |
|---|---|
| Перезагружать машину, менять порядок загрузки, трогать dual-boot | На машине два ОС (Arch + Windows), переключением управляет владелец |
| Поднимать/останавливать VMware и другие VM | Не относится к задаче |
| Пытаться подключиться по SSH/RDP «на эту же машину» изнутри | Нет такой необходимости, риск зацикливания |
| Запускать `start_driver.ps1 -Clean` (и вообще `-Clean`) | Удаляет `shots\`, `done\`, `logs\` — то есть уже снятые кадры |
| Запускать `queue\*.cmd` вручную «чтобы проверить» без нужды | Каждая команда = один кадр; ручной прогон портит нумерацию |
| Добавлять `pause`/`set /p` в команды очереди | Драйвер делит stdin с командой, ввод уйдёт не туда, прогон повиснет |
| Коммитить/пушить без прямого указания | Владелец сам распоряжается историей |

**Актуальное состояние на 2026-11-16:** четыре Windows-исходника `Lab-05a/x/b/c.c`
и `lab05win_common.h` уже находятся в Git. Предыдущее указание остановиться из-за
отсутствия исходников устарело. Сначала выполните инвентаризацию ниже и проверьте
`git status`; не запускайте `-Clean` и не перезаписывайте чужие локальные изменения.

В репозитории уже есть кадр сборки и кадры Windows-прогона, но их комплект не считается
полностью принятым: в b-сериях обнаружены нулевые ring-кадры до первого выхода, c1 не
зафиксировал первый TID, c2 не сохранил список оставшихся потоков, три пары PNG — точные
дубли, а PE-кадры относятся к процессам с PID/TID, отличными от автоматических серий.
Исправления харнесса и повторная Windows-съёмка требуют согласованной интерактивной
сессии на Windows-машине; не переключайте и не перезагружайте её самостоятельно.
Подробности и критерии приёмки — в [`../АУДИТ_ДОКАЗАТЕЛЬСТВ.md`](../АУДИТ_ДОКАЗАТЕЛЬСТВ.md).

## 1. Предусловия: инвентаризация перед стартом

Открыть **обычный PowerShell** (не ARM64 Native Tools) и выполнить:

```powershell
cd C:\OS5
git status --short
git log --oneline -3

# исходники Windows
Get-ChildItem C:\OS5\lab5\windows -Recurse -Include *.c,*.cpp,*.h |
    Select-Object FullName, Length

# артефакты сборки (должно быть пусто на первом прогоне)
Get-ChildItem C:\OS5\lab5\windows\tools -Filter *.exe -ErrorAction SilentlyContinue
```

Критерий приёмки:

- `Get-ChildItem ... -Include *.c,*.cpp,*.h` печатает **пять** файлов:
  четыре `.c` и общий `lab05win_common.h`;
  `Lab-05a.c` (или `Lab_05a.c`), `Lab-05x.c`, `Lab-05b.c`, `Lab-05c.c`;
- `git status` не показывает чужих незакоммиченных правок, которые вы
  собираетесь перезаписать.

Если список исходников пуст — **остановиться** и сообщить владельцу:
«исходников Windows нет, сборка невозможна», приложив вывод команды. Для текущей
ревизии это означает неполный или неверный checkout: остановиться и синхронизировать
репозиторий с `origin/main`, не переносить POSIX исходники из `lab5\linux`.

## 2. Шаг A. Репозиторий в `C:\OS5`

Рекомендуется короткий путь без пробелов: длинные пути с кириллицей и пробелами
могут осложнить работу `cl`, `cmd /c` и подписи в кадрах.

```powershell
Test-Path C:\OS5
# если False:
git clone <URL-репозитория> C:\OS5
# если репозиторий уже есть в другом месте и это допустимо:
#   скопировать каталог в C:\OS5 (или открыть его как есть, но тогда
#   подставить свой путь вместо C:\OS5 во всех командах ниже)
```

Критерий приёмки: `Test-Path C:\OS5\lab5\windows\tools\run_lab.ps1` → `True`.

## 3. Шаг B. Проверка MSVC ARM64

```powershell
where.exe cl
# если пусто — проверить установленный компонент:
& "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" `
    -latest -products * -requires Microsoft.VisualStudio.Component.VC.Tools.ARM64 `
    -property installationPath
```

Критерий приёмки: либо `where.exe cl` печатает путь к `cl.exe`, либо `vswhere`
печатает непустой путь к установке VS. `build.cmd` умеет сам вызывать
`vcvarsall.bat arm64` (VS 17/18, Community/Professional/Enterprise/BuildTools,
затем `vswhere`), поэтому отдельное окно ARM64 Prompt не обязательно — но если
`build.cmd` не находит окружение, работать нужно в **«ARM64 Native Tools Command
Prompt for VS»**.

Проверка разрядности компилятора (после `vcvarsall`):

```powershell
& cl 2>&1 | Select-String -Pattern 'ARM64|x64|ARM'
```

## 4. Шаг C. Сборка

```powershell
cd C:\OS5\lab5\windows
.\build.cmd
$LASTEXITCODE
```

Что должно произойти: `build.cmd` печатает `[i] vcvarsall: ...` (или ничего, если
`cl` уже в PATH), затем по блоку `=== <файл>.c ===` на каждый исходник, затем
`=== BUILD OK ===` и список `tools\*.exe`.

Критерий приёмки:

```powershell
Get-ChildItem C:\OS5\lab5\windows\tools\*.exe |
    Select-Object Name, Length, @{n='ARM64';e={ (Get-Command $_.FullName).FileVersion }}
```

- ровно четыре файла: `Lab-05a.exe`, `Lab-05x.exe`, `Lab-05b.exe`, `Lab-05c.exe`;
- `$LASTEXITCODE` = `0`;
- ни одного `warning C4xxx`/`error C2xxx` в выводе (W4 включён намеренно).

Разрядность конкретного exe:

```powershell
(Get-Item .\tools\Lab-05b.exe).VersionInfo.FileDescription
# либо: dumpbin /headers .\tools\Lab-05b.exe | Select-String 'machine'
#       ARM64 = AA64, x64 = 8664
```

Если `BUILD FAILED` — читать `done\01.txt` после прогона или вывод самой
команды; типовые причины в §11.

## 5. Шаг D. Сухая проверка харнесса без съёмки

Сначала — оффлайн-тесты самого харнесса (не требуют Windows API):

```powershell
cd C:\OS5\lab5\windows\tools
pwsh -NoProfile -File .\test_harness.ps1      # если установлен PowerShell 7
# без pwsh: powershell -NoProfile -ExecutionPolicy Bypass -File .\test_harness.ps1
```

Критерий приёмки: `=== ИТОГ: ok N, провал 0, пропущено 1 ===` (на Windows
smoke-прогон драйвера пропускается — он эмулирует `cmd.exe` через `sh`).

Затем — прогон драйвера **вживую, но без кадров**:

```powershell
cd C:\OS5\lab5\windows\tools
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_lab.ps1 `
    -Root C:\OS5\lab5\windows\tools -NoScreenshot
```

Критерий приёмки:

- в консоли видны строки `PS> cmd /c queue\01_build.cmd` … `queue\09_c_s3.cmd`;
- после каждой команды — `--- конец: HH:mm:ss, код: N ...`;
- `done\01.txt` … `done\09.txt` созданы, в каждом есть `код возврата:`;
- папка `shots\` **пуста** (кадров не было);
- драйвер сам вышел через 20 с после опустения очереди.

Важно: этот прогон уже создал метки `done\NN.done`. Полноценная съёмка их
пропустит, поэтому перед шагом E метки надо убрать:

```powershell
Remove-Item C:\OS5\lab5\windows\tools\done\*.done
# либо сразу: run_lab.ps1 -Force
```

## 6. Шаг E. Съёмка кадров (основной прогон)

Перед стартом:

```powershell
# 1) терминал по умолчанию должен быть Windows Console Host, иначе два
#    процесса Lab-05x окажутся вкладками одного окна и раскладка не сработает:
#    Параметры → Система → Для разработчиков → Терминал  (или свойства conhost)

# 2) шрифт консоли — Consolas / Cascadia Mono (не «растровые шрифты»)

# 3) экран не должен блокироваться: кадры снимаются только с активного
#    рабочего стола; отключить сон/заставку на время прогона

# 4) в очереди ровно 9 команд, каталоги результатов пусты
Get-ChildItem C:\OS5\lab5\windows\tools\queue\*.cmd | Select-Object Name
Get-ChildItem C:\OS5\lab5\windows\tools\shots -ErrorAction SilentlyContinue
```

Запуск:

```powershell
cd C:\OS5\lab5\windows\tools
powershell -NoProfile -ExecutionPolicy Bypass -File .\start_driver.ps1 `
    -Root C:\OS5\lab5\windows\tools
```

`-Clean` **не добавлять**: по умолчанию скрипт ничего не удаляет и только
предупреждает, если в `done\shots\logs` уже есть файлы. Слово `очищено` в его
выводе означает, что кто-то передал `-Clean` — в этом случае остановиться и
проверить, не потеряны ли ранее снятые кадры (их можно достать из git, если они
были закоммичены).

Драйвер откроется отдельным окном слева на экране и пойдёт по очереди. Полный
прогон — 12–20 минут; окно драйвера закрывать нельзя, в нём же печатаются
таблицы процессов и потоков, которые попадают в кадры.

Наблюдение: раз в 1–2 минуты смотреть окно драйвера. Признаки проблем —
`[!] окно для PID ... не найдено`, `[!] дочерних процессов найдено: 0`,
`[!] ТАЙМАУТ`. Реакция — в §11; не прерывать прогон, пока не станет ясно, что
серия испорчена (лучше доснять одну серию заново, чем терять все).

### Что и когда снимается

| # | Команда | Кадр(ы) | Момент |
|---|---|---|---|
| 1 | `01_build.cmd` | `shots\01_build.png` | после сборки, в консоли `=== BUILD OK ===` |
| 2 | `02_a.cmd` | `shots\02_a.png` | после `Lab-05a.exe`: PID/TID/nice/маска/CPU |
| 3 | `03_x.cmd` | `shots\03_x.png` | после ~50 с работы `Lab-05x`, виден хвост вывода |
| 4–6 | `04_b_s1`, `05_b_s2`, `06_b_s3` | планово 6 кадров `05b_s*_a_start`, `_b_ps`, `_c_mid`, `_d_first_finish`, `_d2_after_exit`, `_e_finish` | `a_start` через 3 с, `b_ps` после таблицы процессов, `c_mid` через 10 с, остальные этапы зависят от успешности ring-захвата; имя файла без подтверждённого ring-кадра не доказывает pre-exit состояние |
| 7–9 | `07_c_s1`, `08_c_s2`, `09_c_s3` | планово те же 6 суффиксов с префиксом `05c_s*` | первый worker должен определяться по двум рабочим TID; главный TID не считать worker, а этап принимать только при ненулевом ring-счётчике и подтверждённом оставшемся потоке |

По плану скрипты создают 45 кадров: 9 для отдельных команд и по 6 на каждую из 6 серий.
Кроме них вручную снимаются кадры Process Explorer. В текущем Git-наборе всего 49 PNG,
но три пары изображений полностью совпадают. Поэтому наличие нужного числа файлов ещё не
означает, что все этапы сняты отдельно и правильно.
Локально харнесс создаёт девять `done\01..09.txt`, однако папка `done/` исключена Git.
В репозитории остаются 12 кратких файлов в `logs\`, но нет полного вывода всех команд.

Отдельно, **вручную** (харнесс этого не делает) — Process Explorer для ARM64
(`procexp64a.exe`, запуск от администратора):

1. `View → Show Lower Pane` (`Ctrl+L`), `Lower Pane View → Threads`.
2. Колонки: `Process Performance` → `CPU`, `Priority Class`; `Threads` → `TID`,
   `Priority`; `Process Image` → `Command Line`.
3. Для серии `b` — развернуть `Lab-05b` с двумя `Lab-05x`, снять «до/после»
   для каждой серии, сохранить как `shots\05b_s1_f_procexp.png` и т. п.
4. Для серии `c` — `Properties` процесса `Lab-05c` → вкладка `Threads`.
5. Для `Lab-05a` — `Properties → Image → Affinity` (системная маска).

Ручные кадры снимать, пока серия ещё идёт (или сразу после, пока окна живы),
иначе приоритеты уже нечего показывать.

## 7. Приёмка кадров и логов

### 7.1. Комплектность

```powershell
cd C:\OS5\lab5\windows\tools
(Get-ChildItem .\shots\*.png).Count          # ожидается 45 (+ ручные procexp)
Get-ChildItem .\shots\*.png | Select-Object Name, Length | Sort-Object Name
Get-ChildItem .\done\*.txt | Measure-Object  # 9
Get-ChildItem .\logs | Measure-Object        # 12
```

Плановые имена: `01_build`, `02_a`, `03_x`, `04_b_s1`…`09_c_s3` (9) и по 6 на
каждую серию `05b_s1/s2/s3`, `05c_s1/s2/s3` (36). Это плановая раскладка имён, а не
доказательство успешной съёмки. Файлов `_ring_*.png` быть не должно после завершения,
но сводка обязана показывать ненулевой ringCount для `d_first_finish`; иначе pre-exit
кадр не получен и серия не принимается. Не объединять этапы только потому, что число
PNG совпало с планом; сверять SHA-256 и содержимое каждого кадра.

### 7.2. Техническая проверка кадров (размер, не чёрный ли)

```powershell
Add-Type -AssemblyName System.Drawing
Get-ChildItem .\shots\*.png | Sort-Object Name | ForEach-Object {
    $img  = [System.Drawing.Image]::FromFile($_.FullName)
    $bmp  = New-Object System.Drawing.Bitmap $img
    $pts  = @(
        $bmp.GetPixel([int]($bmp.Width/4),   [int]($bmp.Height/4)),
        $bmp.GetPixel([int]($bmp.Width/2),   [int]($bmp.Height/2)),
        $bmp.GetPixel([int]($bmp.Width*3/4), [int]($bmp.Height*3/4)))
    $lum = 0; foreach ($p in $pts) { $lum += ($p.R + $p.G + $p.B) / 3 }
    '{0,-32} {1,5}x{2,-5} {3,7} KB  яркость={4}' -f $_.Name, $img.Width, $img.Height,
        [int]($_.Length / 1KB), [int]($lum / 3)
    $bmp.Dispose(); $img.Dispose()
}
```

Критерий: у каждого файла `Length` > 50 КБ и `яркость` > 20. Кадр с
`яркость` ≈ 0 — чёрный экран (сессия заблокирована или снимок сделан не с
активного рабочего стола): переснять серию.

### 7.3. Содержательная проверка (читать кадры глазами/OCR)

Открыть каждый кадр в 100 % и сверить с журналом команды: изображение должно показывать
именно тот этап, под которым оно сохранено.

- `01_build` — видно `=== BUILD OK ===` и четыре exe; ни «error C»;
- `02_a` — восемь строк: `Идентификатор процесса`, `Идентификатор потока`,
  `Уровень любезности процесса (nice)`, `... потока`, `Приведённый приоритет`,
  `Маска родственности процесса: <двоичная строка длиной = число CPU>`,
  `Количество процессоров`, `Номер процессора`;
- `03_x` — строки `итерация | PID | TID | класс | приоритет | <число> | CPU`,
  внизу `Итераций: 1000000 ...` и время ≈ 50–90 с;
- `05b_s*_b_ps` / `05c_s*_b_ps` — таблица `PID PPID Имя Класс Потоков База Маска`;
  в серии `b` у детей классы из параметров серии, в серии `c` видны потоки с
  уровнями `Lowest`/`Highest`;
- `*_d_first_finish` — **главный кадр**: он должен быть сохранён до выхода первого
  процесса или потока. На изображении должны быть видны последний результат первого
  участника и продолжающий работать второй. Название файла или текст в кратком отчёте
  сами по себе этого не подтверждают;
- `*_d2_after_exit` — окно завершившегося уже закрыто, выживший продолжает;
- `*_e_finish` — финальный вывод родителя (`Итераций: ... `, время);
- кириллица читаемая, без `?`, `ё`, ромбиков (иначе — растровый шрифт или
  потеря `chcp 65001`).

Критерий серии: в `done\NN.txt` есть `первым завершился дочерний процесс PID`
(для `b`) или `первым завершился поток TID` (для `c`), и в `logs\NN_summary.txt`
совпадают PID/TID, время и список кадров.

### 7.4. Проверка кодов возврата

```powershell
Get-ChildItem .\done\*.txt | Sort-Object Name | ForEach-Object {
    $code = (Select-String -LiteralPath $_.FullName -Pattern '^код возврата: (.+)$').Matches.Groups[1].Value
    '{0}: {1}' -f $_.Name, $code
}
```

Критерий: у `01`…`03` и у серий — `0`. Любой `таймаут (...)` или ненулевой код —
разбирать по §11 и переснимать **только** эту команду (см. §8.2).

## 8. Сохранение артефактов и повторные прогоны

### 8.1. Что сохранять

- `lab5\windows\tools\shots\*.png` — кадры (45 + ручные procexp);
- `lab5\windows\tools\done\01.txt` … `09.txt` — полные тексты вывода;
- `lab5\windows\tools\logs\05b_s1_info.txt`, `05b_s1_summary.txt`, … — сводки
  серий (PID/TID, время, кто завершился первым);
- ручные кадры Process Explorer.

Каталоги `done\` и временные `_ring_*` в git не нужны (`.gitignore` уже
исключает `done/` и `_ring_*.png`), а `shots\` и `logs\` — это сдаваемые
результаты. Коммит делать **только по указанию владельца**, сообщение вида
`lab5(windows): кадры и логи прогона на Windows 11 ARM64`.

### 8.2. Переснять одну команду или серию

Одну команду очереди:

```powershell
cd C:\OS5\lab5\windows\tools
Remove-Item .\done\06.done           # снять метку
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_lab.ps1 `
    -Root C:\OS5\lab5\windows\tools -Force -KeepAlive
# после нужной команды — Ctrl+C в окне драйвера
```

Одну серию без очереди (окно драйвера при этом должно быть на экране слева —
таблица печатается в его консоль, если запускать из неё; при отдельном окне
таблица будет в новом окне и в кадр не попадёт):

```powershell
cd C:\OS5\lab5\windows\tools
powershell -NoProfile -ExecutionPolicy Bypass -File .\capture_05b.ps1 `
    -P1 all -P2 BelowNormal -P3 High -Tag 05b_s2_retry -Layout right
```

Переснятые файлы с суффиксом `_retry` не перезаписывают основные; в отчёт
берутся те, что признаны годными, остальные удалить или пометить в отчёте.

## 9. Итоговый отчёт оператора

Прислать владельцу:

1. `git status --short` и `git rev-parse HEAD` **до** и **после** прогона.
2. Вывод `build.cmd` целиком (или `done\01.txt`).
3. Таблицу кодов возврата из §7.4.
4. Список кадров с размерами (`Get-ChildItem .\shots\*.png | Select Name,Length`).
5. По каждой серии — по одному предложению: кто завершился первым, с какими
   номерами итераций, на каком кадре это видно.
6. Явно: какие шаги выполнены, какие — нет, и все отклонения от этой инструкции.
7. Если чего-то не хватило (исходники, MSVC ARM64, окна не нашлись) — стоп-шаг
   и полный текст ошибки, без «додумывания» результатов.

## 10. Симптомы и что делать

| Симптом | Причина | Действие |
|---|---|---|
| `BUILD FAILED: не найдено ни одного исходника` | под `lab5\windows` нет `Lab-05a/x/b/c.c` | стоп: сначала исходники (см. §0) |
| `BUILD FAILED: не найден vcvarsall.bat` | нет VS с C++/MSVC ARM64 | запустить из «ARM64 Native Tools Command Prompt» или доустановить компонент |
| `[FAIL] нет исходника Lab-05b.c` при частичном наборе | часть файлов отсутствует | положить все четыре; сборка намеренно не пропускает отсутствующие |
| `[!] не найден ...Lab-05b.exe` | сборка не прошла | смотреть §4 и `done\01.txt` |
| `[!] окно для PID ... не найдено` | терминал по умолчанию — Windows Terminal | переключить на Windows Console Host и переснять серию |
| `[!] драйвер не найден` / вышел сразу | политика ExecutionPolicy, опечатка в пути | запустить `run_lab.ps1` вручную, прочитать ошибку |
| `[!] дочерних процессов найдено: 0` | `Lab-05b` не стартует `Lab-05x` (`CREATE_NEW_CONSOLE`, имя exe) | проверить контракт в `tools\README.md` §9, пересобрать |
| `[!] ТАЙМАУТ 600 с` | машина медленнее ожидаемого, серия зависла | `-TimeoutSec 900`, переснять серию; проверить, что exe не ждёт stdin |
| Кадры чёрные | сессия заблокирована / снимок с другого рабочего стола | разблокировать, отключить сон, переснять |
| В кадре ромбики/`?` вместо кириллицы | растровый шрифт консоли | Consolas/Cascadia Mono, переснять |
| Слово `очищено` в выводе `start_driver` | передан `-Clean` | проверить, целы ли прежние кадры (git), впредь `-Clean` не передавать |
| `done\NN.txt` с `ошибка драйвера` | сбой запуска команды | читать текст ошибки в файле, разбирать по пути |
