# Харнесс скриншотов ЛР5 (Windows, ARM64)

Комплект для съёмки кадров к лабораторной №5 «Диспетчеризация и планирование»
на Windows 11 ARM64. Одна команда в очереди = один скриншот всего экрана плюс
текстовый лог вывода команды.

Пошаговый порядок работы на Windows-машине (с критериями приёмки на каждом
шаге) — в отдельном файле [`../ИНСТРУКЦИЯ_ОПЕРАТОРУ.md`](../ИНСТРУКЦИЯ_ОПЕРАТОРУ.md).
Этот README описывает сам харнесс и границу «что проверено без Windows».

## 0. Статус (по факту, 2026-11-15)

| Что | Состояние |
|---|---|
| Харнесс (5 `.ps1`, 9 команд очереди, `build.cmd`) | готов, offline-проверки зелёные (см. §9) |
| **Windows-исходники `Lab-05a/x/b/c`** | **отсутствуют — это блокер** |
| Сборка MSVC ARM64, съёмка кадров на Windows | **не выполнялись** |

Блокер подробно:

- под `lab5\windows` нет ни одного `.c`/`.cpp`/`.h`: инвентаризация
  `Get-ChildItem lab5\windows -Recurse -Include *.c,*.cpp,*.h` даёт `0` файлов;
- исходники `lab5\linux\*.c` — POSIX (`pthread.h`, `sched.h`, `unistd.h`,
  `cpu_set_t`, `sched_setaffinity`, `getpriority`), MSVC их не собирает;
- поэтому `build.cmd` **обязан падать** с
  `BUILD FAILED: не найдено ни одного исходника Lab-05*.c`: раньше он печатал
  `[SKIP]` на каждый отсутствующий файл и завершался `BUILD OK` без exe, из-за
  чего пустая сборка выглядела успешной;
- до появления четырёх Windows-версий `.c` (контракт — §8) запускать `build` и
  съёмку бессмысленно: `02_a`–`09_c_s3` не найдут exe.

## 1. Состав

| Файл | Назначение |
|---|---|
| `tools/run_lab.ps1` | драйвер очереди: по очереди выполняет `queue\NN_*.cmd`, печатает вывод, снимает `shots\NN_*.png`, пишет `done\NN.txt` и метку `done\NN.done` |
| `tools/start_driver.ps1` | поднимает драйвер в отдельном консольном окне и проверяет, что он жив; **по умолчанию ничего не удаляет** |
| `tools/capture_05b.ps1` | серия для `Lab-05b`: два дочерних **процесса** `Lab-05x`, раскладка окон, 6 кадров |
| `tools/capture_05c.ps1` | серия для `Lab-05c`: два дочерних **потока**, 6 кадров |
| `tools/lab_common.ps1` | общий код: Win32-обвязка, скриншоты, раскладка окон, таблицы процессов и потоков, разбор маски, `Clear-LabResults` |
| `tools/test_harness.ps1` | offline-проверки харнесса (парсинг, кодировки, пути, helper-функции, таймауты, smoke-прогон драйвера) |
| `tools/queue/01..09_*.cmd` | очередь команд: сборка, `Lab-05a`, `Lab-05x`, три серии `b`, три серии `c` |
| `build.cmd` | сборка четырёх exe под MSVC ARM64 в `tools\` |
| `ИНСТРУКЦИЯ_ОПЕРАТОРУ.md` | пошаговый handoff для работы на Windows: команды, приёмка, симптомы |

Каталог переносится на Windows-машину как есть (через git): все пути в скриптах
берутся относительно каталога скриптов. Единственное исключение —
`Resolve-LabRoot` без `-Root` проверяет `C:\OS5` как удобное место репозитория;
рекомендуемый путь — `C:\OS5`, тогда рабочий каталог харнесса
`C:\OS5\lab5\windows\tools`.

Сборка exe — `..\build.cmd` (MSVC ARM64), exe и obj/pdb кладутся в `tools\`,
то есть рядом с харнессом: `Lab-05b/c` запускают `.\Lab-05x.exe` из своего
текущего каталога, а драйвер работает в `tools\`.

## 2. Окружение

- Windows 11 ARM64, PowerShell 5.1 (`C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`).
  Никаких модулей и установок не требуется, используется только .NET Framework + user32/kernel32.
- Visual Studio с рабочей нагрузкой «Desktop development with C++» и компонентом
  MSVC ARM64. `build.cmd` сам вызывает `vcvarsall.bat arm64` (ищет VS 17/18,
  Community/Professional/Enterprise/BuildTools, затем `vswhere`). Если `cl` уже
  в PATH (ARM64 Native Tools Command Prompt), `vcvarsall` не вызывается.
- Process Explorer для ARM64 — `procexp64a.exe` (для ручных скриншотов приоритетов).

## 3. Быстрый старт (после того, как исходники Windows появились)

```
cd C:\OS5\lab5\windows

build.cmd                              :: 4 exe в tools\, ждём "=== BUILD OK ==="

cd C:\OS5\lab5\windows\tools
powershell -NoProfile -ExecutionPolicy Bypass -File .\test_harness.ps1   :: offline-проверки
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_lab.ps1 -Root C:\OS5\lab5\windows\tools -NoScreenshot
Remove-Item .\done\*.done              :: после сухого прогона снять метки
powershell -NoProfile -ExecutionPolicy Bypass -File .\start_driver.ps1 -Root C:\OS5\lab5\windows\tools
```

Драйвер займёт левую половину экрана, начнёт с `01_build.cmd` и пойдёт по
порядку имён: `02_a`, `03_x`, `04_b_s1`, `05_b_s2`, `06_b_s3`, `07_c_s1`,
`08_c_s2`, `09_c_s3`. Полный прогон — примерно 12–20 минут (по ~1.5–2 мин на
серию `b`, столько же на `c`).

Остановить: `Ctrl+C` в окне драйвера. Продолжить: запустить `start_driver.ps1`
снова — команды с существующей меткой `done\NN.done` пропускаются
(принудительно повторить: `run_lab.ps1 -Force`).

Полезные ключи:

| Ключ | Смысл |
|---|---|
| `start_driver.ps1 -ExitWhenIdle` | драйвер выйдет сам, когда очередь опустеет (по умолчанию висит и ждёт новые `*.cmd`) |
| `start_driver.ps1 -Clean` | **удалить** содержимое `done\`, `shots\`, `logs\` перед прогоном (по умолчанию кадры не трогаются) |
| `start_driver.ps1 -Clean -IncludeQueue` | дополнительно удалить `queue\*.cmd` (восстановление: `git checkout -- lab5/windows/tools/queue`) |
| `run_lab.ps1 -TimeoutSec 900` | таймаут одной команды (по умолчанию 600 с) |
| `run_lab.ps1 -NoScreenshot` | прогон без кадров (быстрая проверка) |
| `run_lab.ps1 -NoSelfLayout` | не двигать окно драйвера в левую половину |
| `capture_05b.ps1 -Layout full` | дочерние окна на весь экран (ручной прогон без драйвера) |
| `start_driver.ps1 -Root C:\OS5` | корень репозитория: скрипт сам найдёт `lab5\windows\tools` по подкаталогу `queue` |

Ручной прогон одной серии, без очереди:

```
powershell -NoProfile -ExecutionPolicy Bypass -File .\capture_05b.ps1 -P1 all -P2 BelowNormal -P3 High -Tag 05b_manual
```

## 4. Очередь и серии

| Команда | Что снимает |
|---|---|
| `01_build.cmd` | `build.cmd`, вывод компилятора |
| `02_a.cmd` | `Lab-05a.exe`: PID, TID, nice и приведённый приоритет потока, маска родственности процесса (двоично), число доступных CPU, номер CPU потока |
| `03_x.cmd` | `Lab-05x.exe`: полный прогон ~50 с (1 млн итераций, задержка 50 мс каждые 1000), в кадр попадёт «хвост» вывода, полный текст — в `done\03.txt` |
| `04_b_s1.cmd` | `b`: все CPU, `Normal` / `Normal` |
| `05_b_s2.cmd` | `b`: все CPU, `BelowNormal` / `High` |
| `06_b_s3.cmd` | `b`: один CPU (маска `1`), `BelowNormal` / `High` |
| `07_c_s1.cmd` | `c`: все CPU, процесс `Normal`, потоки `Normal` / `Normal` |
| `08_c_s2.cmd` | `c`: все CPU, процесс `Normal`, потоки `Lowest` / `Highest` |
| `09_c_s3.cmd` | `c`: один CPU (маска `1`), процесс `Normal`, потоки `Lowest` / `Highest` |

Своя команда добавляется файлом `queue\10_что_угодно.cmd` — драйвер подхватит
его в течение 0.5 с. Внутри должен быть обычный cmd-текст; относительные пути
считайте от `queue\` через `%~dp0` (рабочий каталог драйвера — `tools\`).
Команды очереди не должны читать stdin (`pause`, `set /p`): stdin общий с
драйвером.

Маска `P1` в скриптах нормализуется: `all` → все логические процессоры,
`0x...`/`0b...` → соответствующее число, иначе десятичное. В exe всегда уходит
**десятичное** число.

## 5. Кадры и пункты задания

### Lab-05a и Lab-05x

`shots\02_a.png` — весь вывод `Lab-05a` (маски в двоичном виде, номера CPU)
в консоли драйвера. `done\02.txt` — тот же текст целиком.

Для `Lab-05x` кадр `shots\03_x.png` показывает последние строки; весь протокол
(все 1000 строк) — в `done\03.txt`, по нему же строится вывод о времени
`clock` в конце.

### Lab-05b (серии 1–3), префикс `05b_s1` / `05b_s2` / `05b_s3`

| Кадр | Момент | Что на нём |
|---|---|---|
| `_a_start.png` | через 3 с после старта | заголовки обоих `Lab-05x` рядом, окна разложены |
| `_b_ps.png` | +1.2 с после таблицы | таблица `PID/PPID/класс/потоки/база/маска` в консоли драйвера (эквивалент `ps`) |
| `_c_mid.png` | через 10 с | середина прогона: расхождение итераций уже видно |
| `_d_first_finish.png` | последний кадр перед выходом первого процесса | **главный кадр**: завершившийся процесс показывает свою последнюю итерацию, выживший — текущую |
| `_d2_after_exit.png` | сразу после выхода | окно завершившегося уже закрыто, выживший продолжает |
| `_e_finish.png` | после завершения родителя | итоговый вывод `Lab-05b` |

### Lab-05c (серии 1–3), префикс `05c_s1` / `05c_s2` / `05c_s3`

Те же шесть этапов, но в кадре одно окно `Lab-05c` справа и консоль драйвера
слева, где напечатана таблица потоков (`TID`, `Уровень`, `База`, `Состояние`)
и снимок списка TID. Кадр `_d_first_finish.png` — момент, когда один из потоков
исчез из списка, а второй ещё работает: расхождение итераций двух потоков видно
в одном кадре.

Итого автоматически: 9 кадров очереди + 6 серий × 6 кадров = **45 кадров**,
9 текстов `done\01..09.txt`, 12 файлов в `logs\`.

### Скриншоты Process Explorer — вручную

Харнесс их не делает: Process Explorer нужно настроить один раз и снимать
вручную, пока идёт серия (или сразу после, окна ещё живы).

1. Запустить `procexp64a.exe` от администратора (`Options → Run as administrator`
   либо сразу «от имени администратора»).
2. `View → Show Lower Pane` (`Ctrl+L`), затем `View → Lower Pane View → Threads`.
3. Правый клик по заголовку столбцов → `Select Columns…`:
   - вкладка `Process Performance`: `CPU`, `Private Bytes`, `Priority Class`;
   - вкладка `Threads`: `TID`, `Priority`, `Start Address`, `CPU`;
   - вкладка `Process Image`: `Command Line` (видно маску в аргументах).
4. Для серии `b`: развернуть дерево `Lab-05b` → видно два `Lab-05x`, у каждого
   в столбце `Priority Class` — класс, в `Command Line` — аргументы.
   Кадр «до/после» для каждой серии.
5. Для серии `c`: `Properties` процесса `Lab-05c` → вкладка `Threads`
   (TID + `Priority` двух рабочих потоков); либо нижняя панель в режиме Threads.
6. Для `Lab-05a` при желании — `Properties → Image → Affinity` (системная маска).

Скриншоты Process Explorer кладутся рядом: `shots\05b_s1_f_procexp.png` и т. п.

## 6. Кодировки (важно при правке файлов)

- `.ps1` — **UTF-8 WITH BOM**. PowerShell 5.1 без BOM читает файл как ANSI
  (cp866/cp1251) и превращает кириллицу в мусор. Не пересохраняйте скрипты в
  ANSI и не снимайте BOM (VS Code: «UTF-8 with BOM»).
- `.cmd` — **UTF-8 БЕЗ BOM** плюс `chcp 65001` первой командой. Это осознанное
  отступление от правила «BOM везде»: `cmd.exe` не пропускает BOM и портит
  первую строку файла (`@echo off` перестаёт работать, в консоль летит ошибка).
  Русские `rem`-комментарии в `.cmd` не выводятся, поэтому кодировка безопасна;
  сообщения `echo` идут после `chcp 65001`.
- `.md` — UTF-8 без BOM, LF.
- Вывод дочерних процессов: драйвер ставит `chcp 65001` и читает поток как
  UTF-8 (`[Console]::OutputEncoding`), поэтому кириллица из `Lab-05*.exe`
  (исходники компилируются с `/utf-8`) доходит до экрана и до `done\NN.txt`
  без искажений. Шрифт консоли должен поддерживать кириллицу — `Consolas`,
  `Cascadia Mono` (не «растровые шрифты»).

`tools\test_harness.ps1` проверяет эти правила автоматически (BOM у `.ps1`,
отсутствие BOM у `.cmd`).

## 7. Как это работает

**Драйвер.** Запускается в своём окне (левая половина экрана, `GetConsoleWindow`
+ `MoveWindow`). Для каждой команды: пишет `PS> cmd /c queue\NN_имя.cmd`,
создаёт временную обёртку `done\_NN.run.cmd` с `chcp 65001` и
`call "<команда>" > "<tmp>" 2>&1`, запускает её через `cmd /d /c` с
`ProcessStartInfo` и **дочитывает растущий файл** каждые 200 мс, печатая только
завершённые строки (поэтому UTF-8 не рвётся на границе символа). По окончании —
скриншот всего экрана, `done\NN.txt` (команда, старт/конец, длительность, код
возврата, полный вывод) и `done\NN.done`. Таймаут команды по умолчанию **600 с**:
дерево процессов снимается `taskkill /T /F`, в лог пишется «таймаут», драйвер
идёт дальше.

**Таймауты согласованы.** Внутренние лимиты серии в `capture_05b/05c` — 240 с на
ожидание первого потомка и 240 с на ожидание родителя. Худший случай серии
(3 с старт + 1.2 с таблица + 10 с середина + 240 + 240 + запас) ≈ 495 с, то есть
драйвер (600 с) не убьёт серию раньше, чем она сама сдастся и запишет сводку.
`test_harness.ps1` проверяет это соотношение — при правке таймаутов он упадёт.

**Очистка результатов.** `start_driver.ps1` **не** чистит по умолчанию: кадры и
сводки предыдущего прогона — сдаваемые данные, а не мусор. Если в `done\shots\logs`
что-то есть, скрипт печатает предупреждение и продолжает. Удаление — только
явным `-Clean` (реализовано в `lab_common.ps1:Clear-LabResults`, покрыто тестом).

**Скриншот.** `System.Drawing.Bitmap` + `Graphics.CopyFromScreen` по
`SystemInformation.VirtualScreen` (все мониторы), сохранение в PNG. Перед
захватом вызывается `SetProcessDPIAware()`, иначе при масштабировании 125/150 %
кадр обрезается. Небольшая пауза (200–350 мс) даёт консоли перерисоваться.

**Раскладка окон.** Окно консольного процесса принадлежит не самому процессу, а
`conhost.exe`, поэтому `Get-LabProcessWindows` собирает множество PID =
{процесс} ∪ {его дети `conhost.exe`/`OpenConsole.exe`} и матчит его по
`EnumWindows` + `GetWindowThreadProcessId`. Найденное окно приводится в
нормальное состояние (`ShowWindow(SW_RESTORE)`) и ставится `MoveWindow`:
родитель — сверху справа, два ребёнка — двумя этажами ниже; левая половина
остаётся драйверу с таблицей. Если окно не нашлось за 12 с, печатается
предупреждение и серия продолжается (см. риск про Windows Terminal).
Заголовок консоли драйвера `capture_05*.ps1` меняет на время серии и
восстанавливает в конце, чтобы в кадрах следующих команд был штатный заголовок.

**Кадр «момент выхода первого потомка».** Консольное окно исчезает вместе с
процессом, поэтому «снять ровно в момент» нельзя: между обнаружением выхода
(опрос `Get-Process` каждые 250 мс) и `Save-LabScreenshot` проходит 0.3–0.5 с,
окно уже закрыто. Решение — кольцевой буфер: пока ждём выход, каждые ~0.6 с
снимается кадр в `shots\_ring_<tag>.png` (перезапись одного файла). При
обнаружении выхода последний кадр копируется в `_d_first_finish.png`, то есть
это кадр, снятый не позже ~0.6 с до выхода, — на нём завершившийся процесс
ещё виден со своей последней итерацией. Сразу после этого снимается
`_d2_after_exit.png` (выживший + таблица драйвера). Оба кадра идут в отчёт.
Для 05c признак завершения потока — исчезновение TID из списка потоков
процесса (снимок TID берётся на этапе `_b_ps`).

## 8. Контракт для `Lab-05*.c` (что должны уметь исходники)

Харнесс рассчитывает на следующее — это же надо держать в виду при написании
четырёх Windows-версий `.c` (единственный незакрытый блокер, см. §0):

1. Имена: `Lab-05a.c` (допускается POSIX-написание `Lab_05a.c`), `Lab-05x.c`,
   `Lab-05b.c`, `Lab-05c.c`; кладутся в `lab5\windows\` или `lab5\windows\src\`.
   exe — `Lab-05a.exe`, `Lab-05x.exe`, `Lab-05b.exe`, `Lab-05c.exe`, все в
   одном каталоге (`tools\`). `Lab-05b/c` запускают `Lab-05x.exe` из своего
   текущего каталога (`.\\Lab-05x.exe`), консоль ребёнка — отдельным окном
   (`CreateProcess` + `CREATE_NEW_CONSOLE`), иначе окна не разложить и кадры
   серии бессмысленны.
2. Аргументы `Lab-05b`: `argv[1]` — маска родственности (**десятичная**,
   принимайте также `0x`/`0b` на всякий случай), `argv[2]`, `argv[3]` — классы
   приоритетов: `Idle|BelowNormal|Normal|AboveNormal|High|RealTime`
   (`SetPriorityClass`). `Lab-05c`: `argv[1]` — маска, `argv[2]` — класс
   процесса, `argv[3]`, `argv[4]` — приоритеты потоков:
   `Idle|Lowest|BelowNormal|Normal|AboveNormal|Highest|TimeCritical`
   (`SetThreadPriority`). Регистр — как в списке.
3. `Lab-05x`: 1 000 000 итераций, каждые 1000 — задержка **50 мс** (поправка
   преподавателя; в документе 200 мс) и строка: номер итерации, PID, TID, класс
   приоритета процесса, приоритет потока, приведённый числовой приоритет, номер
   CPU; в конце — время с запуска (`clock`). Задержка — активным ожиданием
   (`QueryPerformanceCounter`/`Sleep(0)` в цикле), а не `Sleep(50)`: иначе
   поток отдаёт CPU и приоритеты не проявляются (замерено в Linux-части).
4. После финальной строки — пауза `Sleep(1500)` перед `return`, затем выход.
   Это нужно кадру `_d_first_finish`: кольцевой буфер успевает застать финальные
   числа. `_getch()`/`pause` в конце **не** ставить: харнесс определяет
   завершение по выходу процесса и повиснет до таймаута.
5. Вывод — в `stdout` построчно, UTF-8 (`/utf-8` + `SetConsoleOutputCP(65001)`
   в начале `main`), без `\r`-магии и без перерисовки экрана (`\b`, `\r`,
   `SetConsoleCursorPosition`) — иначе текст в кадре и в `done\NN.txt` поедет.
6. `Lab-05a` печатает то, что требует задание, включая системную маску
   родственности (`GetProcessAffinityMask` + `GetSystemInfo`).

## 9. Что проверено (и чем именно)

Все проверки — offline, на macOS, без Windows API и без единого снятого кадра.

```
$ cd lab5/windows/tools && pwsh -NoProfile -File ./test_harness.ps1
=== ИТОГ: ok 78, провал 0, пропущено 0 ===
```

`test_harness.ps1` проверяет:

1. **Парсинг** всех шести `.ps1` через `[Parser]::ParseFile` — 0 ошибок;
2. **Кодировки**: у всех `.ps1` есть BOM, у `build.cmd` и девяти `queue\*.cmd`
   BOM отсутствует (иначе `cmd.exe` ломает первую строку);
3. **Пути в очереди**: каждая команда ссылается на существующий `.ps1`/`.cmd`
   через `%~dp0`, имена exe — `Lab-05a/05x.exe`;
4. **Helper-функции** `lab_common.ps1`: `Get-LabQueueNumber`, `Format-LabMask`
   (`255/8 → 11111111`, `1/8 → 00000001`, `0/4 → 0000`), `ConvertTo-LabMask`
   (`7`, `0x1f → 31`, `0b101 → 5`, `all` → 2^CPU−1), `Resolve-LabRoot`
   (каталог с `queue` находится, каталог без `queue` даёт понятную ошибку),
   `Clear-LabResults` (чистит `done/shots/logs`, очередь оставляет; с
   `-IncludeQueue` удаляет и её);
5. **Таймауты**: 600 с у драйвера ≥ худшего случая серии (495 с);
6. **Очистка в `start_driver`**: параметр называется `-Clean` (удаление — только
   по нему), `-NoClean` больше не нужен;
7. **`build.cmd`**: падает при отсутствии исходников, ищет `src\`, вызывает
   `vcvarsall arm64`;
8. **Smoke-прогон `run_lab.ps1 -NoScreenshot`** на изолированной копии каталога
   (`cmd.exe` эмулируется шимом на `sh`, exe не нужны): порядок команд по
   именам, `done\NN.txt` с командой/кодом возврата/выводом, метки `.done`,
   ненулевой код (7) пробрасывается, таймаут фиксируется и убивает дерево,
   неполная последняя строка дописывается `-Final`, временные файлы
   `done\_*.run.cmd`/`_*.out.tmp` удаляются, `-NoScreenshot` не создаёт PNG,
   повторный запуск не перевыполняет готовые команды.

Дополнительно руками, на копии каталога:

- `start_driver.ps1` без `-Clean` при существующих `shots/done/logs` печатает
  предупреждение и **сохраняет** файлы; с `-Clean` — очищает `done/shots/logs`
  и оставляет `queue\`;
- `start_driver.ps1` предупреждает об отсутствии исходников сборки и exe
  (на macOS дальше падает на `Start-Process -WindowStyle`, это ожидаемо).

Чего эти проверки **не** дают: реального `cmd.exe`, MSVC, окон `conhost`,
`CopyFromScreen`. Список — §12.

## 10. Известные допущения и риски

- **Скрипты не прогонялись на Windows.** Проверены синтаксис, helper-логика и
  драйвер (на эмуляции `cmd.exe`). Первый живой прогон — на Windows-машине,
  возможны правки; порядок с критериями приёмки — в `ИНСТРУКЦИЯ_ОПЕРАТОРУ.md`.
- **Нет Windows-исходников** (§0) — блокер сборки; без них `01_build.cmd`
  честно падает, остальные команды останутся без exe.
- **Windows Terminal вместо консоли.** Если в Windows 11 терминалом по
  умолчанию назначен Windows Terminal, новые консольные процессы открываются
  вкладками одного окна: два `Lab-05x` окажутся в одном окне, раскладка и
  кадры серии `b` станут непригодны (`Параметры → Запуск → Терминал по
  умолчанию → Windows Console Host`). Скрипты в этом случае печатают
  `[!] окно для PID ... не найдено`. Альтернатива без смены настройки —
  запускать `conhost.exe Lab-05x.exe` вручную, но `Lab-05b` запускает детей сам.
- **Окно драйвера.** Драйвер ставит своё окно в левую половину через
  `GetConsoleWindow` + `MoveWindow`. В Windows Terminal это скрытое окно псевдоконсоли,
  поэтому перемещения не будет (ещё одна причина работать в conhost); отключить
  самопозиционирование — `run_lab.ps1 -NoSelfLayout`.
- **Масштабирование экрана.** Скрипты DPI-aware, но при 150 % шрифт в консоли
  крупный: в половину экрана влезает меньше строк. Если текст обрезается,
  запускайте серии с `-Layout full`.
- **Шрифт консоли.** «Растровые шрифты» не содержат кириллицы — в кадре будут
  ромбики. Поставить `Consolas`/`Cascadia Mono` в свойствах окна.
- **Политика запуска скриптов.** Везде передаётся `-ExecutionPolicy Bypass`;
  если запрещено групповой политикой, выполнить
  `Set-ExecutionPolicy -Scope Process Bypass -Force` в текущем окне.
- **Антивирус/SmartScreen** может спросить про свежесобранные exe — разрешить.
- **Драйвер и stdin.** Команды очереди не должны читать stdin (`pause`,
  `set /p`): stdin общий с драйвером и ввод уйдёт не туда.
- **Тайминги.** 05b/05c рассчитаны на прогон ~55–70 с на серию; при 1 CPU
  (серия 3) дольше. Внутренние лимиты серии — 240 с + 240 с, таймаут команды
  драйвера — 600 с; при нехватке увеличьте `-TimeoutSec` и
  `-ParentTimeoutSec`/`-RunTimeoutSec` согласованно (тест в §9 следит за
  соотношением).
- **Кириллица в путях.** Поддерживается (все пути в кавычках), но лучше держать
  репозиторий в `C:\OS5`.

## 11. Диагностика

| Симптом | Причина / что делать |
|---|---|
| `BUILD FAILED: не найдено ни одного исходника` | под `lab5\windows` нет `Lab-05a/x/b/c.c` — сначала исходники (§0, §8) |
| `[FAIL] нет исходника X.c` | отсутствует один из четырёх файлов; `build.cmd` намеренно не пропускает |
| `BUILD FAILED: не найден vcvarsall.bat` | нет VS с C++/MSVC ARM64 либо нестандартный путь — запустить из ARM64 Native Tools Command Prompt |
| `[!] не найден ...Lab-05b.exe` | не собрано: `queue\01_build.cmd`, смотреть `done\01.txt` |
| `[!] окно для PID ... не найдено` | Windows Terminal как терминал по умолчанию (см. §10) |
| `[!] дочерних процессов найдено: 0` | `Lab-05b` не стартует `Lab-05x` (имя exe/путь/`CREATE_NEW_CONSOLE`) |
| Кадры есть, но пустые/чёрные | сессия заблокирована (экран блокировки) — скриншоты снимаются только с активного рабочего стола |
| В кадре ромбики вместо кириллицы | растровый шрифт консоли |
| `[i] ... уже есть N файлов - они НЕ удаляются` | штатное предупреждение: старые результаты сохранены; удалить — `-Clean` |
| Драйвер вышел сразу | `powershell -NoProfile -ExecutionPolicy Bypass -File .\run_lab.ps1` вручную покажет ошибку |
| Тест `test_harness.ps1` падает на таймаутах | `-TimeoutSec` драйвера стал меньше худшего случая серии — поднять |

## 12. Что нельзя проверить без Windows

- Компиляцию MSVC ARM64 (`/utf-8 /O2 /W4`, пути `/Fo:` `/Fd:` `/Fe:`).
- Разбор `build.cmd` самим `cmd.exe`: логика прочитана статически, на macOS
  `cmd.exe` нет (wine не установлен) — первый прогон и есть проверка.
- `CopyFromScreen`, DPI-awareness, `VirtualScreen` на реальном мониторе.
- Матчинг окон через `EnumWindows` + `conhost.exe` и саму раскладку.
- Кодировку консоли (`chcp 65001` + `[Console]::OutputEncoding`) на живом
  `Lab-05*.exe`.
- Что `Get-Process`/`Get-CimInstance` отдают `ProcessorAffinity`,
  `PriorityClass`, `Threads[*].PriorityLevel` на ARM64.
- Поведение терминала по умолчанию (conhost vs Windows Terminal) и тайминги
  кольцевого буфера.
