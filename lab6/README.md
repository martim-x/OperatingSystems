## Уровень 4–5

- Windows: `Lab-06a` использует критическую секцию, `Lab-06b` – именованный мьютекс, `Lab-06c` – бинарный семафор. Право на выполнение интервала 30–60 включительно получает один участник за раз. `Lab-06d` использует событие с ручным сбросом; дочерние процессы начинают после сигнала на входе родителя в итерацию 16.
- Linux: `Lab-06a` использует `pthread_mutex_t`, `Lab-06b` – POSIX-семафор в разделяемой памяти. Для `Lab-06b` можно передать два пути `/dev/pts/…` из отдельных панелей `tmux` (их показывает `tty`). Дочерние процессы пишут в свои псевдотерминалы, общий вывод сохраняется для проверки по ролям и PID.
- Команды сборки и проверки указаны в `windows/README.md` и `linux/README.md`.

## Уровень 7–8

Общий исходный код C++20 находится в `parallel/`. Для сборки на Linux выполнить `sh build.sh` из этой папки; на Windows – `build.cmd` из Visual Studio Developer Command Prompt. Для проверки выполнить `python -B test_parallel.py build`.

- `Lab-06-conds 10 0 100 50 150` – ограниченный FIFO-буфер. Две условные переменные сигнализируют о появлении элемента и свободного места. На Windows используется `CRITICAL_SECTION`, в Linux – `pthread_mutex_t`. Каждые пять секунд выводится статистика. По умолчанию производство прекращается через 15 секунд; потребитель обрабатывает остаток. Параметр `--seconds N` меняет длительность.
- `Lab-06-bar 4 7 3` – сложение семи матриц 3×3 четырьмя потоками. Матрицы генерируются до запуска потоков; после первого барьера потоки складывают частичные результаты атомарно, после второго параллельный результат сверяется с последовательным и печатается.

## Уровень 9–10

```text
python -B lab6/algorithms/Lab-06-dl.py

python -B lab6/algorithms/Lab-06-bank.py --task2 2
python -B -m unittest discover -s lab6/algorithms -v
```

- **Задача 1 (с. 6).** Начальный `Work = (0, 1, 0, 2, 1)`. Сначала может завершиться P2: `Work = (0, 2, 0, 3, 1)`. Затем P3: `Work = (0, 2, 0, 3, 2)`. P1 и P4 остаются во взаимоблокировке: P1 ждёт экземпляр RS1, оба экземпляра которого у P4; P4 ждёт экземпляр RS3, который у P1. Полный граф распределения и запросов: `algorithms/task1.dot`.
- **Задача 2 (с. 6).** В напечатанных данных безопасного `x` нет. По ресурсу в пятом столбце у A выделена 1 единица, свободна 1, другие процессы не удерживают этот ресурс. Максимум A равен 3 при общем запасе 2. `x` изменяет только третий столбец и эту нехватку не устраняет.
- **Алгоритм Банкира (с. 7).** При `Available = (3, 3, 2)` одна безопасная последовательность: P1 → P3 → P4 → P0 → P2. Запрос P1 `(1, 0, 2)` можно удовлетворить, запрос P4 `(3, 3, 0)` оставляет систему в небезопасном состоянии. При отказе исходное распределение сохраняется.

Для защиты задачи 1 и 2 по условию нужно отдельно оформить на бумаге. Отчёт собран из `build/report.json` в `lab6.docx` и `lab6.pdf`. Скриншоты находятся в `build/скрины/`, полные журналы снятых прогонов – в `выводы/`.
