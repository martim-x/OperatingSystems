# ЛР4 (Windows) — Управление потоками

Исходники и результаты фактических прогонов. Задание: `labs/ОС ЛР4.pdf`.
Комментариев в коде нет (требование ТЗ). Вывод — через `printf`, кириллица перекодируется
`console_ru.h` (UTF-8 → OEM 866).

## Состав

| Файл | Что делает | Уровень |
|---|---|---|
| `Lab-04a.c` | два дочерних потока (55 и 130 итераций) + 100 итераций в главном, ожидание завершения всех | 4-5 |
| `Lab-04b.c` | как 4a, но главный поток считает свой цикл сам; поток 1 приостанавливается на 30-й итерации и возобновляется на 70-й, поток 2 — на 40-й и возобновляется после цикла главного | 4-5 |
| `Lab-04c.c` | как 4a, но поток 2 принудительно завершается на 50-й итерации (`TerminateThread`) | 4-5 |
| `Lab-04d.c` | список потоков своего процесса через Tool Help Library | 4-5 |
| `Lab-04p.c` | поиск простых чисел в потоках, буфер в TLS через WinAPI (`TlsAlloc`/`TlsSetValue`), запись в общий массив без синхронизации | 7-8 |
| `Lab-04p2.c` | то же, но TLS через `__declspec(thread)` | 7-8 |
| `Lab-04pi.c` | число Пи рядом Лейбница на волокнах (fibers), завершение по `Ctrl+C` (`SetConsoleCtrlHandler`) | 9-10 |
| `lab04_common.h` | функция `Lab_04x`: `PID - TID - №итерации - символ пользователя - символ ФИО`, задержка 400 мс | 4-5 |
| `console_ru.h` | перекодировка вывода UTF-8 → cp866 | — |
| `tools/test_pi.ps1` | тест `Lab-04pi`: запуск в отдельной консоли и корректная посылка `Ctrl+C` | 9-10 |

`Lab_04x` печатает символы `User-6d4ec851` и ФИО `Маруско Тимофей` циклически, каждый в своём темпе.

## Сборка

```cmd
cd lab4\windows
build.cmd
```

MSVC ARM64, `/utf-8`, `/O2`. Собираются все семь приложений, `BUILD OK` — 7 `.exe`.

## Запуск

```cmd
Lab-04a.exe
Lab-04b.exe
Lab-04c.exe
Lab-04d.exe
Lab-04p.exe 4 1 200000
Lab-04p2.exe 4 1 200000
Lab-04pi.exe 4 2000
```

`Lab-04p`/`Lab-04p2`: `<количество потоков> <нижний порог> <верхний порог>`.
`Lab-04pi`: `<количество волокон> <элементов на переключение>`, завершение — `Ctrl+C`.

## Результаты фактических прогонов (2026-10-26, Windows 11 ARM, MSVC ARM64)

| Приложение | Проверено | Факт |
|---|---|---|
| `Lab-04a` | 291 строка вывода, завершилось само | `Все потоки завершены.`, TID потоков 4488 и 7496 |
| `Lab-04b` | 303 строки, все метки в нужном порядке | «Поток 1 приостановлен на итерации 30», «Поток 2 приостановлен на итерации 40», «Поток 1 возобновлён на итерации 70», затем «Все потоки завершены.» |
| `Lab-04c` | 215 строк | «Поток 2 завершён принудительно на итерации 50 (последняя итерация потока: 50)» |
| `Lab-04d` | мгновенный вывод | `Процесс PID=5012`, `Поток 1: TID=8052`, `Всего потоков в процессе: 1` |
| `Lab-04p` 4 1 200000 | 17 984 простых числа | 0,0028 с |
| `Lab-04p2` 4 1 200000 | 17 984 простых числа (совпадает) | 0,0216 с |
| `Lab-04p` 8 1 2000000 | 148 933 простых числа | 0,0397 с |
| `Lab-04p2` 8 1 2000000 | 148 933 простых числа (совпадает) | 0,0789 с |
| `Lab-04pi` 4 2000 | `Ctrl+C` → корректный выход, код 0 | 3 897 294 000 слагаемых, Пи = 3.141592653333754, погрешность 2,56e-10 |

Число простых чисел совпадает с табличным (π(2·10⁵) = 17 984, π(2·10⁶) = 148 933) — потоки
ничего не теряют и не дублируют, несмотря на запись в общий массив без синхронизации:
буфер в TLS у каждого потока свой, а позиция в общем массиве берётся атомарным
`InterlockedIncrement`.
