# ЛР5 (Windows) — статус прогона на этой машине

Машина: Windows 11 x64, AMD Ryzen 7 7700X (8 ядер / 16 логических процессоров).
Учётная запись: `User-6d4ec851`. Рабочий каталог прогона:
`C:\Users\User-6d4ec851\OS5\lab5\windows\tools`.
Сборка: MSVC (VS 18 Community), `build.cmd` → `vcvarsall x64`, флаги `/utf-8 /O2 /W4`,
`=== BUILD OK ===`, четыре exe (`Lab-05a/x/b/c.exe`, PE-заголовок 0x8664 — x64).

Параметры по указанию владельца: **1 000 000 итераций**, **задержка 50 мс** каждые 1000 итераций
(в задании 200 мс), задержка активная (busy-wait по `QueryPerformanceCounter`).

## Как снимались кадры

- Каждый замер идёт в своём консольном окне; заголовок окна = имя исполняемого файла
  (`Lab-05a.exe`, `Lab-05x.exe`, `Lab-05b.exe`, `Lab-05c.exe`), в кадре только приглашение,
  команда и вывод программы.
- Process Explorer снимается **во время той же серии**: окно 1150×690 (1/3 ширины, 1/2 высоты),
  фильтр `Lab-05`, в дереве видны `Lab-05b.exe` и два `Lab-05x.exe` с PID этой серии,
  в нижней панели (Threads) — TID и Base Pri.
- Ключевой кадр `*_d_first_finish` берётся из кольцевого буфера: последний кадр,
  снятый при живом завершающемся участнике.

## Что видно на ключевых кадрах

- **b3** (`05b_s3_d_first_finish.png`, 1 CPU): в верхнем окне `BelowNormal` (PID 30676, TID 22748)

  (PID 32496, TID 29164) — **1 000 000**, `clock 52.121 с`, приведённый приоритет 13.
- **c3** (`05c_s3_d_first_finish.png`, 1 CPU): поток `Highest` (TID 23148) дошёл до
  **1 000 000**, `clock 50.082 с`; поток `Lowest` (TID 8512) в этот момент — **14 000** итераций.
- **b1** (`05b_s1_d_first_finish.png`, все CPU): первый участник (TID 27132) на последнем
  кадре перед выходом — **980 000** итераций; оба участника завершаются в пределах одного опроса.
- **c1/c2** (все CPU): оба потока завершаются почти одновременно, отдельного кадра
  «один уже вышел, второй продолжает» нет; кадр показывает обоих у финальных итераций.
  Это и есть наблюдаемый результат: при свободных процессорах приоритет не даёт выигрыша.

## Process Explorer

Для каждой серии снят кадр `*_f_procexp.png` (для b — ещё `*_f_procexp2.png`):
фильтр `Lab-05`, дерево `Lab-05b.exe` → два `Lab-05x.exe`, PID совпадают с логами серии,
в нижней панели Threads — TID и Base Pri выбранного процесса.

Проверка классов приоритета независимо от PE (PowerShell `Get-Process`) на серии b3:
`32820 → BelowNormal, BasePriority 6`; `37168 → High, BasePriority 13`.

## Ограничения и отклонения

- Задержка **50 мс** вместо 200 мс по заданию — указание владельца; письменного подтверждения
  преподавателя в репозитории нет.
- В `Lab-05x` добавлена пауза **1.5 с** перед началом цикла (`LAB05_START_PAUSE_MS`).
  Без неё на одном CPU низкоприоритетный дочерний процесс не успевает создать и отрисовать
  своё консольное окно, поэтому кадр «оба окна рядом» не получается. Пауза не входит
  в измеряемое `clock` время.
- `build.cmd` выбирает архитектуру по хосту (`arm64` на ARM64, иначе `x64`),
  переопределение — `set LAB5_ARCH=...`.
- `Lab-05a/x/b/c` выставляют заголовок консоли `SetConsoleTitleA("<имя exe>")`,
  чтобы в кадре не было пути запуска.
