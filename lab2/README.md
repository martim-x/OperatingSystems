## 1. Что такое переменные окружения и зачем они нужны

**Переменная окружения** — это именованная строка, которую операционная система хранит
в памяти и передаёт каждому запускаемому процессу. Формально это пара «имя → значение»,
живущая в окружении процесса, а не в файле на диске.

Окружение наследуется: дочерний процесс получает копию окружения родителя при запуске.
Поэтому переменная, заданная в одном окне консоли, видна всем программам, запущенным
из этого окна, — но не видна в другом окне.

**Зачем нужны.** Чтобы системе и программам не приходилось передавать конфигурацию
через аргументы командной строки, откуда её нужно было бы разбирать в каждой программе.
Окружение решает три задачи:

1. **Путь поиска.** Оболочка при запуске программы сначала просматривает каталоги
   из переменной `PATH`. Пользователь добавляет свой каталог в `PATH` один раз — и после
   этого вызывает свои утилиты по короткому имени, без полного пути.
2. **Параметры конфигурации.** Система передаёт программам, где искать данные
   (`HOME`, `USERPROFILE`), куда складывать временные файлы (`TEMP`, `TMP`),
   как выводить результат (`LANG`, `LC_ALL`, кодовая страница консоли).
3. **Настройки пользователя без прав администратора.** Через собственные переменные
   пользователь передаёт приложениям свои пути и параметры, не меняя системные
   настройки глобально.

Ключевое свойство: переменные окружения не хранятся в реестре или в файле конфигурации
оболочки как «настройки» — они существуют только в памяти процесса. Изменение переменной
в одной сессии не влияет на остальные сессии, пока значение не будет записано в профиль
(`setx`, `.bashrc`, `profile`).

**Как смотреть и менять:**

| Действие | Windows (cmd / PowerShell) | Linux (bash) |
|---|---|---|
| Показать все переменные | `set` / `set \| more`, `$env: \| more` | `env`, `printenv` |
| Показать одну переменную | `echo %PATH%`, `$env:PATH` | `echo $PATH` |
| Изменить в текущей сессии | `set X=1` / `$env:X=1` | `X=1` или `export X=1` |
| Изменить постоянно | `setx X 1` (новые процессы) | добавить в `~/.bashrc` |
| Удалить | `set X=` | `unset X` |

**Важное различие.** В `cmd` переменная хранится как строка и подставляется синтаксически:
`%PATH%`. Чтобы увидеть изменённое значение внутри одного и того же блока `cmd`,
нужно отложенное расширение `setlocal EnableDelayedExpansion` и запись `!VAR!` —
обычный `%VAR%` раскрывается до выполнения блока. В `bash` и `PowerShell` подстановка
вычисляется в момент обращения, поэтому такой проблемы нет: `$PATH` и `$env:PATH` всегда
актуальны.

## 2. Самая важная переменная окружения для работы в консоли

**`PATH`** — переменная поиска исполняемых файлов. Это подтверждается результатом
прогона: в ней на этой машине **10 каталогов** (`выводы/уровень_6-7/19_set_path.txt`,
`выводы/уровень_8-9/01_path_count.txt`).

Когда пользователь вводит имя программы, оболочка **не ищет файл во всей файловой
системе**. Она последовательно проверяет каждый каталог из `PATH` и запускает первый
найденный исполняемый файл. Именно поэтому:

- `python` находит нужную программу, хотя пользователь не писал полный путь;
- если каталог убрать из `PATH`, команда перестаёт находиться, хотя файл на диске лежит;
- системные команды (`cmd`, `dir`, `systeminfo`) работают всегда — их каталоги
  прописаны в `PATH` системой;
- порядок каталогов в `PATH` имеет значение: первый найденный выигрывает, поэтому
  пользовательский каталог, поставленный в начало, перекрывает системный.

Практические следствия, которые видно из прогона:

- добавление своего каталога: `set PATH=C:\mytools;%PATH%` — точка с запятой в Windows,
  двоеточие в Linux;
- проверка, откуда запустится программа: `where python` (Windows) / `which python` (Linux);
- разделитель элементов: `;` в Windows и `:` в Linux — это одно из ключевых отличий.

## 3. Анализ ключевых переменных окружения

Значения взяты из фактического вывода `set` (`выводы/уровень_6-7/17_set_all.txt`)
и `set_path` (`выводы/уровень_6-7/18_set_key.txt`).

| Переменная | Назначение | Зачем нужна на практике |
|---|---|---|
| `PATH` | Список каталогов поиска исполняемых файлов | Позволяет запускать программы по короткому имени |
| `USERPROFILE` / `HOME` | Домашний каталог пользователя | Базовая точка для относительных путей и хранения настроек |
| `TEMP` / `TMP` | Каталог для временных файлов | Место, куда приложения пишут промежуточные данные |
| `PATHEXT` | Список расширений, которые cmd воспринимает как исполняемые | Объясняет, почему `script` находит `script.bat`, а `script.txt` — нет |
| `COMPUTERNAME` | Имя узла в сети | Участвует в идентификации компьютера |
| `USERNAME` | Имя учётной записи | Используется в bat-файлах для вывода пользователя |
| `PROCESSOR_ARCHITECTURE` | Архитектура процессора | Здесь `ARM64` — подтверждает, что система 64-разрядная на базе ARM |
| `OS` | Название и версия ОС | Исходные данные для `systeminfo` |
| `NUMBER_OF_PROCESSORS` | Число логических ядер | Полезно при разборе загрузки процессора |
| `HOMEDRIVE`, `HOMEPATH` | Диск и путь домашнего каталога | Альтернативная запись пути к домашнему каталогу |

Простой разбор полного вывода на этой машине показывает, что переменные делятся на три
группы: системные (`OS`, `COMPUTERNAME`, `PROCESSOR_ARCHITECTURE`), пользовательские
(`USERNAME`, `USERPROFILE`, `APPDATA`) и служебные (`PATHEXT`, `NUMBER_OF_PROCESSORS`).
Отдельно стоит группа переменных вида `=C:` — это внутреннее представление переменных
текущего диска в `cmd`: для каждого диска хранится текущий каталог, поэтому
`cd D:` переходит в каталог, который был последним на диске `D:`.

Сравнение с Linux: набор переменных меньше, но роли те же. Вместо `USERPROFILE` —
`HOME`, вместо `PATHEXT` — набор исполняемых прав (`chmod +x`), вместо `%TEMP%` —
`TMPDIR`. В Linux переменные в основном **экспортируются** (`export PATH=...`), чтобы
попасть в окружение дочерних процессов; в cmd этого нет — все переменные всегда видны.

## 4. Почему команды названы именно так

Имена команд в Windows сокращены от полных английских выражений. Это не аббревиатура
произвола, а традиция, уходящая в команды MS-DOS 1981 года, где память была дорогой,
и длина имени имела значение.

| Команда | Полное название | Смысл |
|---|---|---|
| `cd` | **Ch**ange **D**irectory | сменить текущий каталог |
| `md` | **M**ake **D**irectory | создать каталог |
| `rd` | **R**emove **D**irectory | удалить каталог |
| `dir` | **D**irect**o**r**y** | вывести список содержимого каталога |
| `copy` | **Co**py | копировать |
| `move` | **Mo**ve | переместить |
| `ren` / `rename` | **REN**ame | переименовать |
| `del` | **DEL**ete | удалить |
| `type` | **TYPE** | вывести содержимое текстового файла |
| `find` | **FIND** | найти подстроку |
| `sort` | **SORT** | сортировать |
| `attrib` | **ATTRIButes** | показать или изменить атрибуты |
| `xcopy` | e**X**tended **COPY** | расширенное копирование |
| `fc` | **F**ile **C**ompare | сравнить файлы |
| `set` | **SET** | задать или показать переменную |
| `echo` | **ECHO** | вывести строку |

По этой же логике построены и Linux-команды, но по-другому:

| Windows | Linux | Полное название |
|---|---|---|
| `cd` | `cd` | change directory — совпадает |
| `dir` | `ls` | **l**i**s**t |
| `del` | `rm` | **r**e**m**ove |
| `md` | `mkdir` | **m**a**k**e **dir**ectory |
| `rd` | `rmdir` | **r**e**m**ove **dir**ectory |
| `copy` | `cp` | **c**o**p**y |
| `move` | `mv` | **m**o**v**e |
| `ren` | `mv` | move — переименование через перемещение |
| `type` | `cat` | **cat**enate — «склеить», откуда и имя |
| `find` | `grep` | **g**lobal **r**egular **e**xpression **p**rint |
| `attrib` | `chmod` / `ls -l` | **ch**ange **mod**e |
| `echo` | `echo` | совпадает |
| `sort` | `sort` | совпадает |
| `systeminfo` | `uname -a` | **u**nix **name** |

Интересное исключение — `grep`: это не `find`, потому что `find` в unix уже занят
другим назначением (поиск файлов по дереву каталогов). Имя образовано от команды
редактора `ed`/`sed`: `g/re/p` — «глобально, регулярное выражение, печатать».

## 5. Правила наименования параметров

Параметры команд следуют тем же правилам, что и сами команды, с добавлением типовых
префиксов-указателей.

**Windows.** Параметры бывают трёх видов:

- **ключи** (флаги) — короткие, без значения, включают режим: `/s`, `/b`, `/f`,
  `/r`, `/q`. Запись через косую черту исторически унаследована от MS-DOS;
- **ключи со значением** — те же ключи, но с параметром: `/o:n` (сортировка по имени),
  `/i:5` (интервал 5 секунд), `/A:R` (только атрибут «только для чтения»);
- **длинные параметры** — через `param(...)` в PowerShell: `-Interval`, `-FileIn`,
  `-Help`. Именно поэтому в собственных скриптах на PowerShell использованы длинные
  имена: они читаются лучше коротких.

Расшифровка ключей, встретившихся в работе:

| Ключ | Откуда сокращение | Значение |
|---|---|---|
| `/s` | **s**ub**d**irectories | рекурсивно, по подкаталогам |
| `/b` | **b**are | краткий вывод, только имена (`dir /b`, `xcopy /b` — двоичный режим) |
| `/f` | **f**orce | принудительно, без подтверждения |
| `/r` | **r**ead-only | учитывать файлы «только для чтения» |
| `/q` | **q**uiet | без вывода |
| `/y` | **y**es | отвечать «да» на все вопросы |
| `/p` | **p**ause | постраничный вывод с паузой |
| `/o` | **o**rder | порядок сортировки (`/o:n` — по имени, `/o:d` — по дате) |
| `/a` | **a**ttributes | фильтр по атрибутам |
| `/i` | **i**nteractive | считать источник каталогом, если он не существует |

**Linux.** Там параметры длинные и всегда с двойным дефисом:

| Параметр | Полная форма | Значение |
|---|---|---|
| `-l` | **l**ong format | подробный вывод |
| `-a` | **a**ll | включая скрытые (`.`-файлы) |
| `-r` | **r**ecursive | рекурсивно |
| `-h` | **h**uman-readable | размеры в КБ/МБ/ГБ |
| `-n` | **n**umeric, **n**one | вывод номеров строк, пустых строк |
| `--help` | — | справка по команде |

**Общее правило наименования:** сокращение строится от значимых букв английского слова,
берутся согласные или первые буквы слогов; параметры, требующие значения, отделяются от
значения двоеточием (`/o:n`, `-Interval 3`), флаги значения не имеют. Регистр не важен:
`dir /b` и `DIR /B` эквивалентны в Windows, `-Interval` и `-INTERVAL` — в PowerShell.

## 7. Ключевые отличия Windows и Linux, проверенные на практике

1. **Разделитель пути** — `\` в Windows, `/` в Linux. В PowerShell допускаются оба.
2. **Разделитель списка в PATH** — `;` в Windows, `:` в Linux. Ошибка здесь ломает поиск команд.
3. **Регистр имён файлов** — в Windows имя файла не различает регистр (`TXT1.txt` = `txt1.TXT`), в Linux различает.
4. **Кодировка консоли** — Windows по умолчанию OEM cp866, Linux — UTF-8. Это порождает мусор вида «я┐╜я┐╜», когда страницу переключают не на той стороне (см. п. 8).
5. **Ввод с консоли** — `copy con` и `Read-Host` в Windows игнорируют перенаправленный stdin и блокируются навсегда; в Linux `cat` с перенаправлением работает штатно.
6. **Атрибуты файлов** — в Windows есть «только для чтения», «архивный», «скрытый», «системный», для них есть отдельные команды `attrib` и ключи `xcopy /A /K`. В Linux атрибутов нет, есть только права доступа `chmod` (`rwx`).
7. **Замена файлов** — в Windows `replace` требует формы `каталог1\* каталог2\ /S`, без `\*` команда молча ничего не делает.
8. **Символы, зарезервированные оболочкой** — `%` невозможно передать в программу через командную строку `cmd`, `^` нужно удваивать (`^^`). В bash зарезервированы `$`, `` ` ``, `*`, `?`.
9. **Подстановка переменных** — `cmd` раскрывает `%VAR%` до выполнения блока (нужен `!VAR!` с `EnableDelayedExpansion`), bash и PowerShell вычисляют значение в момент обращения.
10. **Список файлов и подстановка** — `copy *.txt` в Windows не требует кавычек, в bash путь с пробелами обязательно заключать в кавычки.
11. **Размеры файлов** — Windows: `dir` показывает байты; Linux: `ls -l` — байты, `ls -lh` — в КБ/МБ/ГБ.
12. **Объектная модель** — PowerShell возвращает типизированные объекты, которые передаются по конвейеру, а не текст; `cmd` и `bash` работают только с текстом.

## 8. Грабли, на которые наступали при выполнении

Практические выводы из прогона — то, что на защите обычно спрашивают.

- **`chcp 65001` внутри bat-файла ломает вывод.** Переключение страницы означает, что cmd пишет дальнейший вывод в UTF-8, а сборщик читает его как cp866 — получается мусор вида «я┐╜я┐╜темя┐╜я┐╜». Правильно: не переключать страницу в bat-файле.
- **`.ps1` с кириллицей обязан быть UTF-8 с BOM.** PowerShell 5.1 без BOM читает файл как ANSI и рвёт парсер на русских словах — отказ `Отсутствует ")"`.
- **Перенаправление в конце цепочки `&` действует только на последнюю команду.** Вывод предыдущих (for, if, echo) уходил в stdout и терялся. Правильно: ставить перенаправление на каждую часть цепочки, разделитель — в конец строки.
- **Скобочная обёртка `(команда) > файл` ломается на данных со скобками.** `%PATH%` содержит `Program Files (x86)`, и закрывающая скобка в данных обрывала блок — вывод получался пустым.
- **`for %%F in (*.txt) do type nul > %%F` обнуляет только первый файл:** cmd не закрывает дескриптор перенаправления между проходами. Правильно: `type nul > имя` поимённо.
- **`set /a` внутри `if`-блока даёт пустой результат:** `%var%` раскрывается до выполнения блока. Нужны `setlocal EnableDelayedExpansion` и `!var!`.
- **`scp` на Windows: обратный слэш — буква в имени, а не разделитель пути.** `scp file host:C:/lab2_sync/queue\00.cmd` создаёт файл `queue\00.cmd` в корне и рапортует об успехе. Нужен прямой слэш.
- **`del` с маской `*.*` удаляет и сам каталог,** если он опустел. После этого `scp` перестаёт работать, а прогон молча стоит.
- **Знак `^` нужно удваивать (`^^`),** знак `%` через `cmd` не передаётся вовсе.

## 9. Вопросы после лабораторной — краткие ответы с командами

Сводка по темам всех уровней. Команды приведены в том виде, в каком они реально
выполнялись на машине, поэтому с ними можно сверяться со снимками из
`lab2/windows/скрины/` и `lab2/windows/выводы/`.

### Навигация и каталоги

**Как перейти в каталог по абсолютному и относительному пути?**
Абсолютный путь начинается с буквы диска или корня: `cd /d C:\lab2_sync\OS2\task_01i\Русский`.
Ключ `/d` обязателен — без него `cd` не переключит диск. Относительный путь считается
от текущего каталога: `cd ..\English`, где `..` — на уровень выше.

**Как узнать, где мы находимся?**
`cd` без аргументов — в Windows; `pwd` — в Linux. Полный путь: `echo %CD%` в `cmd`,
`$PWD` в PowerShell, `$PWD.Path` в bash.

**Как создать вложенную структуру каталогов одной командой?**
Windows: `md OS2\task_01j\sub\dir\full\path` — `md` создаёт и все промежуточные.
Linux: `mkdir -p OS2/task_01j/sub/dir/full/path` — ключ `-p` создаёт промежуточные
и не падает, если каталог уже есть. Без `-p` Linux требует создавать по одному.

**Чем `rd` отличается от `rm` в Linux?**
`rd` удаляет только **пустой** каталог. Для непустого нужен `rd /s` (с ключом `/q`
для подавления вопросов) или `rd /s /q` для полного молчаливого удаления. В Linux
`rmdir` работает так же — только с пустым каталогом, а `rm -r` удаляет любой.

### Копирование и перемещение

**Как скопировать все txt-файлы из одного каталога в другой?**
Windows: `copy /y OS2\tasks_tmp\*.txt OS2\task_01a\`
Linux: `cp OS2/tasks_tmp/*.txt OS2/task_01a/`
Ключ `/y` в Windows отвечает «да» на вопрос о перезаписи. В Linux ключ `-i`
наоборот запрашивает подтверждение, а `-f` подавляет вопросы.

**Как объединить два файла в третий?**
Windows: `copy txt1.txt + txt2.txt merged.txt`
Linux: `cat txt1.txt txt2.txt > merged.txt`
Знак `+` в `copy` — не сложение, а признак объединения нескольких источников.

**Чем `copy` отличается от `xcopy`?**
`copy` умеет копировать только файлы и не заходит в подкаталоги. `xcopy` работает
с деревом каталогов: `/E` — включая пустые подкаталоги, `/S` — рекурсивно,
`/I` — считать источник каталогом (иначе задаст вопрос), `/Y` — без подтверждений,
`/A` — только файлы с атрибутом «архивный», `/K` — сохранить атрибуты при копировании.
На практике: простое копирование — `copy`, копирование дерева с сохранением
атрибутов — `xcopy /E /A /K /I /Y`.

**Как переименовать расширение у всех файлов каталога?**
Windows: `ren OS2\task_01e\*.txt *.bmp`
Linux: циклом `for f in *.txt; do mv "$f" "${f%.txt}.bmp"; done`
Кавычки в Linux обязательны: без них имя с пробелом разобьётся на несколько аргументов.

**Чем `move` отличается от `ren`?**
`ren` только переименовывает в пределах одного каталога. `move` переносит файл
в другой каталог, сохраняя имя (а с ключом `/Y` — без подтверждения). В Linux
и то и другое делает `mv`.

**Что делает `replace` и почему она молчит?**
`replace` заменяет файлы в одном каталоге файлами из другого. Форма обязательно
с маской: `replace OS2\task_01d_1\* OS2\task_01d_2\ /S`. Без `\*` в первом
аргументе команда не выводит ничего — считает, что заменять нечего.

### Просмотр и удаление

**Как сравнить два файла и сохранить результат?**
Windows: `fc /n file1.txt file2.txt > result.txt`
Linux: `diff file1.txt file2.txt > result.txt`
Ключ `/n` показывает номера строк.

**Как удалить файл с подтверждением и без?**
С подтверждением: `del OS2\task_01g\txt1.txt` — спросит `File to Delete (Y/N)?`.
Без вопроса: `del /f` (`/f` — force). Ключ `/p` наоборот заставит спросить там,
где обычно не спрашивают, то есть у скрытых и системных файлов.

**Как удалить все файлы, кроме «только для чтения»?**
Ключ `/a` фильтрует по атрибутам: `del /f OS2\task_01g\plain*.txt` удаляет обычные
файлы, а `readonly.txt` с атрибутом «только для чтения» остаётся. Обратная операция —
`del /f /a:s`, удалить только системные файлы.

**Как посмотреть содержимое файла?**
`type file.txt` в Windows, `cat file.txt` в Linux. Имя команды в Linux —
от «concatenate» (склеить), отсюда и смысл.

**Как найти подстроку в файле?**
Windows: `find "Иванов" OS2\students.txt` — ищет построчно.
Linux: `grep "Иванов" students.txt` — шаблон по умолчанию базовый (буквально),
регулярные выражения включаются ключом `-E`.

**Как вывести список файлов каталога постранично и в алфавитном порядке?**
Windows: `dir /p /o:n C:\Windows` — `/p` постранично с паузой, `/o:n` сортировка
по имени (по дате — `/o:d`, по размеру — `/o:s`).
Linux: `ls -l | less`, по алфавиту `ls` сортирует сам по умолчанию.

**Как узнать версию BIOS?**
Windows: `systeminfo > OS2\systeminfo.txt & findstr /i "BIOS Version" OS2\systeminfo.txt`
Linux: `sudo dmidecode -s bios-version` или `cat /sys/class/dmi/id/bios_version`.
Ключ `/i` у `findstr` игнорирует регистр.

### Перенаправление и конвейеры

**Что делают `>` и `>>`?**
`>` — перенаправить вывод в файл, создав его заново (старое содержимое пропадает).
`>>` — дописать в конец, сохранив прежнее содержимое. Это базовый механизм создания
списков студентов: `echo Иванов>> students.txt`.

**Как создать файл и одновременно записать в него пустую строку?**
`type nul > file.txt` в Windows — устройство `nul` читает пустоту, файл создаётся
нулевого размера. В Linux: `: > file.txt` (пустая команда в левой части).

**Что такое конвейер?**
Соединение двух команд через `|`: stdout первой становится stdin второй.
Пример — `dir /b C:\Windows | find /c ".exe"` считает количество exe-файлов.
В Linux то же: `ls -l | grep "^-" | wc -l`.

**Почему вывод команды пропадает, если в цепочке с `&` есть `echo`?**
Перенаправление `>` в конце строки действует только на последнюю команду цепочки.
Вывод предыдущих уходит в консоль. Решение — поставить перенаправление на каждую
часть цепочки.

### Сценарии

**Как передать параметры в bat-файл и получить их?**
Параметры доступны как `%1`, `%2`, `%3` — по порядку. `%0` — имя самого bat-файла.
Строка всех параметров: `%*`. В Linux: `$1`, `$2`, `$@`, имя скрипта — `$0`.

**Почему `set /a` внутри `if` даёт пустой результат?**
`%var%` раскрывается до выполнения блока, поэтому изменение переменной в той же
командной строке не видно. Нужен отложенный разбор: `setlocal EnableDelayedExpansion`
и обращение через `!var!` вместо `%var%`.

**Как посчитать выражение в bat-файле?**
`set /a result = a + b`. Знаки: `+ - * / %` — остаток от деления, скобки для
приоритета. Деление на ноль `set /a` не проверяет — нужно проверять самому:
`if %b% EQU 0 echo деление на ноль невозможно`.

**Как получить имя файла, его папку и дату изменения?**
В bat: `%~n0` — имя без расширения, `%~p0` — полный путь, `%~t0` — дата изменения,
`%~dp0` — путь с завершающим обратным слэшем. Модификатор `~n` отбрасывает путь,
`~p` оставляет только путь, `~t` — только время.

### Переменные окружения

**Что такое переменная окружения и зачем она нужна?**
Именованная строка в памяти ОС, передаваемая каждому процессу при запуске.
Нужна, чтобы системе и программам не передавать конфигурацию аргументами: через `PATH`
находятся программы, через `HOME`/`USERPROFILE` — домашний каталог, через `TEMP` —
где писать временные файлы. Переменные наследуются дочерними процессами и живут
только в памяти, пока их не запишут в профиль.

**Какая переменная самая важная для консоли и почему?**
`PATH` — список каталогов поиска исполняемых файлов. Оболочка при вводе имени
программы не ищет файл по всей файловой системе, а проверяет каталоги из `PATH`
по очереди и запускает первый найденный. Поэтому программа находится без полного
пути, перестаёт находиться при удалении каталога из `PATH`, а пользовательский
каталог в начале списка перекрывает системный.

**Как посмотреть все переменные и одну конкретную?**
`set` — все; `echo %PATH%` — одна. В PowerShell: `$env: | more`, `$env:PATH`.
В Linux: `env` или `printenv`, `echo $PATH`.

**Как задать переменную?**
Windows: `set X=1` — до конца сессии, `setx X 1` — постоянно (для новых процессов).
Linux: `X=1` — в текущем шелле, `export X=1` — чтобы попала в дочерние процессы.
Либо добавить строку в `~/.bashrc`.

**Что означают переменные вида `=C:` в выводе `set`?**
Это внутреннее хранение текущего каталога для каждого диска. Благодаря этому
`cd D:` возвращает в тот каталог на диске `D:`, где вы находились в последний раз.

### PowerShell, уровень 8

**Почему `calc.ps1` с ключом `-FileIn` вместо параметра `$FileIn`?**
Объявленный параметр в PowerShell становится позиционным и первым же значением
перехватывается: `calc.ps1 2+3*4` пытался прочитать файл с именем `2+3*4`.
Разбор `$args` вручную внутри скрипта снимает проблему.

**Как обрабатывать приоритет операций в калькуляторе?**
Разбирать выражение по уровням приоритета, а не одним шаблоном: сначала возведение
в степень `^`, затем `* / %`, затем `+ -`. Один общий шаблон не разбирает `2+3*4`
и путает номер группы при использовании именованных групп регулярного выражения.

**Почему `Read-Host` не подходит для автоматического прогона?**
`Read-Host` игнорирует перенаправленный stdin и блокируется навсегда — драйвер,
запустивший скрипт, зависает. Поэтому для автоматизации источник входа задаётся
явно: параметром `-FileIn` читается файл, построчно.

**Почему в PowerShell 5.1 файл с кириллицей обязан быть с BOM?**
PowerShell без BOM читает файл как ANSI (в этой системе cp1251), русские слова
превращаются в мусор и парсер падает с ошибкой `Отсутствует ")"`. Файл должен быть
UTF-8 **с BOM** и с переводами строк CRLF.

**Как получить размер процесса в мегабайтах?**
`[math]::Round((Get-Process -Id $pid).WorkingSet64 / 1MB, 2)` — свойство
`WorkingSet64` даёт размер рабочей области в байтах.

**Как посчитать элементы в строке?**
Строка в PowerShell — это коллекция символов, поэтому работает свойство `Count`:
`($env:PATH -split ';').Count`. Разделитель `;` в Windows и `:` в Linux.

### Мониторинг процессов, уровень 9

**Почему в мониторе нельзя использовать `Clear-Host`?**
При перенаправлении вывода `Clear-Host` не очищает экран, а посылает управляющие
последовательности в файл, и на выходе получается мусор. В автоматическом прогоне
экран не нужен — нужен только текст таблицы.

**Как ограничить бесконечный цикл для съёмки кадра?**
Добавить параметр `-Count`, по умолчанию `0` (бесконечный цикл, как в задании),
а для автоматического прогона передать конкретное число кадров.

**По чему сортировать процессы для топа по CPU и по памяти?**
По суммарному времени процессора `CPU` — это счётчик, накопленный за всё время
жизни процесса, то есть чем дольше живёт процесс, тем больше значение. По памяти —
`WorkingSet64`.
