## 3. Как снимать (механика, проверена)

**Консольные кадры — через драйвер:**

1. Положить файл `<имя>.cmd` в `C:\lab3_sync\queue\` в кодировке **cp866** (это кодовая страница консоли).
   Имя файла = имя будущего PNG без расширения, например `task11_three_proc.cmd` → драйвер сохранит `C:\lab3_sync\shots\task11_three_proc.png` (он режет имя по первому `_`).
2. Запустить обработку: `schtasks /run /tn lab3drv`.
3. Забрать кадр из `C:\lab3_sync\shots\`, лог — `C:\lab3_sync\driver.log`.

**GUI-кадры (Process Explorer, Диспетчер задач) — через задачи `lab3gui*` и скрипт `tools/gui_shots.ps1`:**
скрипт запускается в интерактивной сессии (сеанс 1), потому что SSH живёт в сеансе 0 и рабочий стол не видит.

**Требования к кадру:**
- консоль: кроп клиентской области окна, апскейл до 2100 px, без заголовка окна, без вкладок терминала, без рабочего стола;
- GUI: всё окно целиком, без перекрывающих окон, без курсора на важных строках.

## 4. Грабли (проверено на практике, не наступать)

1. SSH-сессия — сеанс 0, рабочий стол не виден, `PrintScreen` оттуда не работает. Только `schtasks /IT`.
2. `SendKeys` зависит от раскладки: при русской латиница превращается в кириллицу. Текст вводить через буфер (`Set-Clipboard` + `Ctrl+V`).
3. `GetConsoleWindow()` в Windows Terminal бесполезен — окно ищется перечислением по классам `ConsoleWindowClass` / `CASCADING_HOSTING_WINDOW_CLASS`.
4. Process Explorer: нижняя панель — `Ctrl+L`, режим Handles — `Ctrl+H`, и только когда фокус в дереве (`TreeListWindowClass`). Меню через `GetMenu`/`PostMessage` не работает — интерфейс неменюшный.
5. `Add-Type`: один класс на скрипт, иначе конфликт типов; ошибки компиляции не видны без `try/catch`.
6. Очередь пишется в cp866; `chcp 65001` ставить нельзя — программы перекодируют вывод сами (`console_ru.h`).
7. Диспетчер задач: UIA не находит ни поле поиска, ни вкладки — клик по координатам.
8. `procexp64.exe` под драйвером не стартовал (`window not found`) — пробовать `procexp64a.exe` (ARM64).
