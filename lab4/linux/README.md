# ЛР4 (Linux) — Управление потоками

Исходники и результаты фактических прогонов на Arch Linux ARM (aarch64, 6 ядер,
gcc 16.1.1). Задание: `labs/ОС ЛР4.pdf`. Комментариев в коде нет.

## Состав

| Файл | Что делает | Уровень |
|---|---|---|
| `Lab-04px.c` | два дочерних потока (50 и 125 итераций) + 100 итераций в главном, ожидание завершения | 4-5 |
| `Lab-04p.c` | поиск простых чисел в потоках, TLS через `pthread_once` + `pthread_key_t` | 7-8 |
| `Lab-04p2.c` | то же, TLS через `__thread` | 7-8 |
| `Lab-04pi.c` | число Пи рядом Лейбница на волокнах (`ucontext`), завершение по `Ctrl+C` | 9-10 |
| `Lab-03primes.c` | процессный аналог из ЛР3 для сравнения производительности | 7-8 |
| `lab04_common.h` | `lab04x`: PID - TID - №итерации - символ пользователя - символ ФИО, задержка 400 мс | 4-5 |
| `build.sh` | сборка всех приложений | — |
| `bench.sh` | серия замеров и `bench.csv` | 7-8 |
| `lab4_sync/` | драйвер скриншотов в Konsole | — |

`lab04x` печатает символы `User-6d4ec851` и ФИО `Марушко Тимофей` циклически.

## Сборка

```sh
cd lab4/linux
./build.sh
```

`gcc -O2 -pthread -Wall -Wextra`, `BUILD OK` — 5 исполняемых файлов.

## Запуск

```sh
./Lab-04px
./Lab-04p 4 1 200000
./Lab-04p2 4 1 200000
./Lab-04pi 4 5000
./Lab-03primes 4 1 200000
```

`Lab-04p`/`Lab-04p2`: `<потоки> <низ> <верх>`.
`Lab-04pi`: `<волокна> [элементов на переключение]`, завершение — `Ctrl+C`.

## Результаты фактических прогонов (2026-11-08, Arch Linux ARM, 6 ядер)

| Приложение | Проверено | Факт |
|---|---|---|
| `Lab-04px` | 275 строк, завершилось само | `Все потоки завершены.`, TID 1058, 1059, 1060 |
| `Lab-04p` 4 1 200000 | 17 984 простых числа | 0,002091 с |
| `Lab-04p2` 4 1 200000 | 17 984 простых числа (совпадает) | 0,001540 с |
| `Lab-03primes` 4 1 200000 | 17 984 простых числа (совпадает) | 0,007898 с |
| `Lab-04pi` 4 5000 | `Ctrl+C` → корректный выход | 4 561 087 987 слагаемых, Пи = 3.141593536054970, погрешность 8,82e-07 |

Число простых чисел совпадает с табличным: π(2·10⁵) = 17 984, π(2²⁰) = 82 025,
π(2²¹) = 155 611. Потоки ничего не теряют и не дублируют: буфер в TLS у каждого
свой, позиция в общем массиве берётся атомарным `atomic_fetch_add`.
