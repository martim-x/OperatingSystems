Введение
Цель лабораторной работы - освоение процесса установки операционной системы, получение навыков базовой настройки и конфигурации, создание пользовательских учётных записей и подготовка рабочего места для типовых задач.
Для достижения цели определены задачи:
установить операционную систему семейства Windows NT (Windows 11);
установить операционную систему семейства Linux (Arch Linux) в режиме Dual Boot без использования упрощённых установщиков;
создать на обеих системах пользователя с именем User-6d4ec851, полученным хешированием полного ФИО по алгоритму JOAAT на сайте Sordum;
собрать с помощью графических утилит информацию об аппаратной конфигурации на обеих системах и построить рукотворную схему аппаратной конфигурации согласно шинной архитектуре.
Обе операционные системы устанавливаются на одну виртуальную машину гипервизора VMware Fusion, работающую на компьютере Apple MacBook Pro с процессором Apple M1 Pro архитектуры ARM64.

СОЗДАНИЕ И НАСТРОЙКА ВИРТУАЛЬНОЙ МАШИНЫ
	•	Запуск мастера создания машины
Установка обеих операционных систем выполняется на одной виртуальной машине VMware Fusion на компьютере Apple MacBook Pro с процессором Apple M1 Pro. Процессор имеет архитектуру ARM64, поэтому для установки используются сборки систем под ARM. Создание машины начинается с главного окна гипервизора. Запуск мастера создания виртуальной машины представлен на рисунке 1.1.
В главном окне VMware Fusion нажимается кнопка добавления новой виртуальной машины. На экране появляется диалоговое окно выбора способа установки операционной системы: установка с диска или образа (Install from disc or image), импорт существующей виртуальной машины (Import) или перенос физического компьютера с Windows (Migrate). Данный этап - точка входа в мастер создания виртуальной машины.
(Скриншот: главное окно VMware Fusion с открытым диалогом Select the Installation Method)
Рисунок 1.1 – Вызов мастера создания виртуальной машины
Выбор пункта установки с образа переводит мастера к указанию файла ISO - этот шаг рассматривается в следующем подразделе.
Выбор установочного образа
Установка выполняется с ISO-образа Windows 11 для архитектуры ARM64, скачанного заранее. Выбор образа показан на рисунках 1.2 и 1.3.
В диалоге выбора способа установки выбран пункт установки с диска или образа и нажата кнопка Use another disc or disc image. Открылось окно выбора файла, в котором указывается заранее скачанный образ Windows 11 для архитектуры ARM64 (Win11_25H2_Russian_Arm64.iso). Образ выбирается вручную, так как ARM-версии Windows нет в списке готовых образов Fusion.
(Скриншот: окно выбора файла с указанным ISO-образом Windows 11 ARM64)
Рисунок 1.2 – Выбор установочного образа Windows 11 ARM64
Выбранный образ подключён к виртуальной машине: в окне мастера отображается имя подключённого ISO-файла. На этом этапе образ уже привязан к будущей машине как виртуальный установочный диск. Нажимается кнопка Continue для перехода к следующему шагу мастера.
(Скриншот: окно мастера с подключённым образом и кнопкой Continue)
Рисунок 1.3 – Подключение образа к виртуальной машине
На этом подготовка носителя завершена: мастер определил образ как установочный диск будущей виртуальной машины и готов к идентификации устанавливаемой системы.
1.3 Выбор гостевой операционной системы
Мастер определяет и предлагает выбрать гостевую операционную систему. Выбор показан на рисунке 1.4.
Выбирается пункт Windows 11 64-bit Arm - сборка Windows 11 под архитектуру ARM64, соответствующая процессору Apple M1 Pro хост-машины. Корректный выбор архитектуры критичен: образ x86_64 на этом процессоре нативно не исполняется. Нажимается Continue.
(Скриншот: окно выбора гостевой ОС с выделенным пунктом Windows 11 64-bit Arm)
Рисунок 1.4 – Выбор гостевой операционной системы Windows 11 64-bit Arm
После указания архитектуры мастер переходит к настройке микропрограммы виртуальной машины, от которой зависит возможность загрузки устанавливаемой системы.
Настройка прошивки и шифрования диска
Для Windows 11 обязательным требованием является загрузка в режиме UEFI. Настройка прошивки и шифрования показана на рисунках 1.5 и 1.6.
На шаге выбора микропрограммы (firmware) выбирается режим UEFI и устанавливается флажок UEFI Secure Boot - защищённая загрузка. UEFI - обязательное требование Windows 11; Secure Boot в связке с шифрованием виртуального диска обеспечивает проверку подписи загрузчика на этапе старта системы. Нажимается Continue.
(Скриншот: окно выбора прошивки с выбранным UEFI и установленным флажком UEFI Secure Boot)
Рисунок 1.5 – Включение режима UEFI Secure Boot
Гипервизор предлагает включить шифрование виртуального диска. Выбирается автоматический режим: пароль шифрования генерируется автоматически. Сгенерированный пароль сохраняется в надёжном месте - без него доступ к содержимому виртуального диска невозможен. Нажимается Continue.
(Скриншот: окно включения шифрования диска с автоматической генерацией пароля)
Рисунок 1.6 – Включение шифрования виртуального диска
Включение UEFI Secure Boot и шифрования повышает защищённость машины и согласуется с требованиями Windows 11 к загрузке. Все предварительные параметры заданы, остаётся подтвердить создание машины.
Завершение создания машины
Мастер отображает итоговую сводку конфигурации виртуальной машины. Сводка показана на рисунке 1.7.
В сводке перечислены подключённый образ, гостевая система, прошивка, шифрование. Нажимается кнопка завершения создания. Тонкая настройка ресурсов (процессоры, память, диск) выполняется после создания в окне настроек машины.
(Скриншот: сводка конфигурации виртуальной машины перед завершением мастера)
Рисунок 1.7 – Итоговая конфигурация виртуальной машины
Мастер завершён: виртуальная машина создана с типовой конфигурацией. Дальнейшая настройка ресурсов выполняется вручную в окне параметров машины.
Настройка ресурсов виртуальной машины
Созданной машине выделяются вычислительные ресурсы, достаточные для комфортной работы Windows 11 и Visual Studio. Настройка процессоров, памяти и диска показана на рисунках 1.8 и 1.9.
Открывается окно настроек виртуальной машины, раздел Processors and Memory (процессоры и память). Машине выделяется 6 ядер процессора и 8192 МБ (8 ГБ) оперативной памяти. Окно закрывается с сохранением изменений.
(Скриншот: окно настроек, раздел Processors and Memory: 6 процессоров, 8192 МБ)
Рисунок 1.8 – Настройка количества процессоров и объёма памяти
В разделе Hard Disk (жёсткий диск) задаётся размер виртуального диска 100 ГБ и устанавливается флажок предварительного выделения всего дискового пространства - файл диска создаётся сразу целиком, что снижает фрагментацию и повышает предсказуемость производительности. Диск создаётся единым и неразмеченным: разметка на раздел Windows и свободное место под Arch Linux выполняется позже установщиком Windows. Окно закрывается, виртуальная машина готова к установке.
(Скриншот: окно настроек, раздел Hard Disk: размер 100 ГБ, флажок выделения пространства)
Рисунок 1.9 – Настройка размера виртуального диска
После задания процессоров, памяти и диска виртуальная машина полностью готова к установке: подключён образ Windows 11 ARM64, машина получает 6 ядер, 8 ГБ оперативной памяти и единый неразмеченный диск 100 ГБ.
Вывод по разделу
Создана и настроена виртуальная машина VMware Fusion, на которой будут устанавливаться обе операционные системы в режиме Dual Boot. Машина получила 6 ядер процессора, 8 ГБ оперативной памяти и единый виртуальный диск объёмом 100 ГБ с предварительным выделением пространства. Для машины включены режим загрузки UEFI с Secure Boot и шифрование диска.
Единый неразмеченный диск - принципиальное решение: разметку на раздел Windows и свободное место под вторую систему выполняет установщик Windows. Именно сохранённое нераспределённое место позволит позже установить Arch Linux на тот же диск без переустановки Windows. Виртуальная машина готова к установке первой операционной системы.

3 УСТАНОВКА ARCH LINUX ARM
Установка второй операционной системы выполняется на ту же виртуальную машину. Так как хост-процессор Apple M1 Pro имеет архитектуру ARM64, используется Arch Linux ARM - порт дистрибутива Arch Linux для таких процессоров (архив на сайте archlinuxarm.org). У Arch Linux ARM нет установочного ISO: корневая файловая система разворачивается вручную из tarball-архива, без использования упрощённых установщиков, что соответствует повышенному уровню задания (7-9). Вспомогательной средой выступает live-система Ubuntu 26.04 ARM64: она загружается с подключённого ISO-образа и служит инструментом для развёртывания Arch, а на диск не устанавливается.
Перед началом в настройках виртуальной машины отключается UEFI Secure Boot: загрузчик GRUB от Arch Linux ARM не подписан сертификатами Microsoft, поэтому при включённой защищённой загрузке он не запустится (ошибка Security Violation).
3.1 Отключение Secure Boot и загрузка live-Ubuntu
Подготовка к установке и загрузка вспомогательной среды показаны на рисунках 3.1 и 3.2.
В настройках виртуальной машины открывается раздел Advanced и снимается флажок UEFI Secure Boot. Защищённая загрузка проверяет цифровые подписи загрузчиков, а GRUB от Arch Linux ARM выпущен без ключей Microsoft, поэтому для второй системы Secure Boot отключается. Изменение не затрагивает установленную Windows 11.
(Скриншот: настройки виртуальной машины VMware, раздел Advanced, снят флажок UEFI Secure Boot)
Рисунок 3.1 – Отключение UEFI Secure Boot
К виртуальной машине подключается ISO-образ живого дистрибутива Ubuntu 26.04 для архитектуры ARM64, машина перезагружается и загружается с образа. В появившемся меню выбирается пункт Try Ubuntu (попробовать Ubuntu) - система запускается в режиме live без установки на диск. Ключевой для Dual Boot этап установки загрузчика показан на рисунках 3.14 - 3.16.
