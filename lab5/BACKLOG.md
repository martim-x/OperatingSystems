# Бэклог ЛР5 — проблемы Linux-части

**Область аудита:** только Linux-часть уровня 4–5. Набор в `linux/скрины/уровень_4-5/` —
44 PNG, все прогнаны через `vmocr` (вывод: `linux/выводы/уровень_4-5/ocr_кадры.txt`),
сверены с консольными логами и `*_summary.txt` скриптом `tools/check_evidence.py`.
Windows и уровни 7–10 в этот бэклог не входят.

**Общий статус (2026-11-15, проход 2):** Linux-часть уровня 4–5 подтверждена фактическим
набором: 44 кадра / 44 OCR-блока / 44 уникальных SHA-256, шесть серий b1–b3 и c1–c3
завершились штатно (код 0) с обоими участниками, есть кадр Lab-05a и кадр `getcap`.
Открытыми остаются два пункта, не относящихся к самим доказательствам: согласование типа
задержки с преподавателем и удаление временного широкого sudoers-правила (в этом проходе
права не менялись).

## Закрытые пункты

### L5-LNX-01 — нет скриншота Lab-05a → **закрыт**

- **Доказательство:** `01_lab05a.png`; OCR читает `./Lab_05a`, PID/TID 201767, nice процесса
  и потока 0, приведённый приоритет 20, маску родства `111111`, «доступно процессоров: 6»,
  «номер процессора, назначенного потоку: 5».
- **Критерий выполнен:** системной маски в кадре нет (Linux-вариант), все требуемые поля видны.

### L5-LNX-02 — кадр `getcap` вместо sudoers → **закрыт по доказательству, открыт по sudoers**

- **Доказательство:** `02_getcap.png`; OCR читает `getcap "$HOME"/OS5/Lab-05b` и `Lab-05c`
  и вывод `cap_sys_nice=ep` для обоих файлов, плюс `getcap -r` по каталогу `~/OS5`.
- **Безопасность (открыто, вне этого прохода):** кадр со строкой
  `echo "User-6d4ec851 ALL=(ALL) NOPASSWD:ALL" | sudo tee /etc/sudoers.d/lab-agent`
  из набора удалён и в репозиторий не входит. Само правило в системе не проверялось и не
  менялось: удаление `/etc/sudoers.d/lab-agent` и проверка `visudo -c` остаются за владельцем.

### L5-LNX-03 — b3/c3 завершались принудительно → **закрыт**

- **Доказательство b3:** `05b_b3_консоль.txt` — «Дочерний процесс 2 (PID 208153) завершён,
  код 0, t=50.011 с», «Дочерний процесс 1 (PID 208152) завершён, код 0, t=99.736 с»,
  «Оба дочерних процесса обработаны, t=99.736 с».
- **Доказательство c3:** `05c_c3_консоль.txt` — «Поток 2 завершён, t=49.973 с»,
  «Поток 1 завершён, t=99.749 с», «Все потоки завершены».
- **Сводки:** у обеих серий «Lab-05b/c завершился штатно, код 0», длительность 100.5 и 100.7 с.
  Кадр `g_finish` содержит эти же финальные строки (OCR), кадр с кодом `-1` отсутствует.

### L5-LNX-04 — «первое завершение» дублировало финал → **закрыт**

- **Дубли:** в наборе нет ни одной пары PNG с одинаковым SHA-256 (44 уникальных).
  В старом наборе их было три пары (`05b_s1`, `05b_s2`, `05c_s2`), теперь они вне репозитория.
- **Как решено для b1/b2/c1/c2:** участники завершаются с разницей 0.000–0.017 с, то есть внутри
  одного опроса `pgrep` (100 мс). Отдельный кадр «второй ещё работает» физически не снимается,
  поэтому он **не выдумывается**: кадр `e_first` фиксирует первое завершение, а `g_finish`
  содержит строку драйвера «первым завершился участник …; второй … на этот момент уже завершён».
  В README эти четыре серии описаны как «одно окно финиша», а не как «второй жив».
- **Как решено для b3/c3:** разрыв 49.7 с, кадр `f_second` есть и содержит строку
  «первым завершился участник …, второй … на этот момент жив» (OCR подтверждает).
- **Критерий выполнен:** `e_first` не совпадает с `g_finish` по SHA ни в одной серии;
  OCR/лог подтверждают первое завершение, а состояние второго указано явно.

### L5-LNX-05 — кадр b2 от чужого запуска → **закрыт**

- Кадр «второй ещё работает» для b2 не переснимался: в b2 окно финиша одно (дельта 0.017 с),

### L5-LNX-08 — «стартовые» кадры не показывали параметры → **закрыт**

## Открытые пункты

### L5-LNX-07 — семантика задержки и `clock()` для потоков → **закрыт по формулировке, открыт по согласованию**

- В README явно разделены CPU-время `clock()` и стенное время `CLOCK_MONOTONIC`, для 05c
  указано, что `clock()` — это время всего процесса (≈98 с при двух потоках), а не отдельного
  потока; тип задержки (активное ожидание) назван прямо.
- Остаётся внешнее согласование: допустима ли активная задержка вместо блокирующей. Реализация
  в этом проходе не менялась (переделка потребовала бы новых прогонов на машине).

### L5-LNX-11 — два вспомогательных кадра без OCR

- `05b_b1_b_early.png` и `05x_s1_b_early.png` vmocr не распознаёт (пустой блок), хотя визуально
  кадры читаемы. Обязательными этапами они не являются: параметры, состояние процессов и финиш
  подтверждаются кадрами `a_params`, `c_ps`, `d_finish`/`g_finish`. `check_evidence.py` считает
  пустой OCR допустимым только для необязательных этапов и печатает их отдельным списком.
- При следующей съёмке такие кадры лучше переснять (похоже на расфокусировку/момент скролла).

### L5-LNX-12 — поле «последняя итерация» в `*_summary.txt` не является снимком

- В сводках b3/c3 у обоих участников стоит 999 000, хотя на момент первого финиша
  низкоприоритетный был на 4 000–5 000 итераций (видно в консольном логе рядом со строкой
  завершения). Поле отражает конец прогона. В README это оговорено; при следующей правке
  генератора сводок поле стоит переименовать или снимать по времени первого финиша.
